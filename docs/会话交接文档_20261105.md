## 三、关键实证结论（**不要重新推导**）

### 1. 三表拼合：毛利率与股东户数是两个**正交**因子

面板：654,539 行 × 15 列（4,942 只 × 245 时点，2025-10-30 ~ 2026-11-03）；过滤后 362,207 行 / 186 时点 / 4,925 只。收益口径 = 60 日超额，已做时点去均值。

**单维度**：
- 毛利率分位**单调**：Q1(均值 -11.54%) → -6.17%；Q5(58.02%) → -3.73%；**120 日跨度 7.31pp**
- 股东户数变化分位**不单调**：只有 Q5（户数 +32%）明显差（-17.89%），中间三档几乎无区别

**独立性检验（核心）**：OLS 三模型
| 模型 | 毛利率系数 | 户数系数 | 截距 |
|---|---|---|---|
| 只放毛利率 | +2.56% (t=20.9) | — | |
| 只放户数 | — | -2.43% (t=-19.9) | |
| **两个一起放** | **+2.70% (t=22.0)** | **-2.57% (t=-21.0)** | **-1.28% (t=-18) → -0.06% (t=-0.67，不显著)** |

→ **两因子正交、互不包含。**

**二维交叉（60 日超额）**：
| | 户数暴增 | 户数平稳 | 户数减少 |
|---|---|---|---|
| **低毛利** | **-1.97%** | +0.62% | -0.35% |
| **高毛利** | | **+2.26%**（最好格） | |

→ **低毛利本身不是雷，"低毛利 + 散户接盘"才是。** 120 日跨度 5.29pp（60 日为 3.13pp）→ 抓的是**慢性恶化**。

**短板**：①绝对幅度小（3.13pp/60日）②资金流方向预测力弱 ③**有效样本远小于表面**（户数一季度才更新，同一财报被重复铺进约 60 个交易日）。

**当日横截面漏斗（11-04）**：三表拼合 5,075 只 → 低毛利(≤17.70%) 1,691 → +户数暴增(≥2.78%) 486 → +主力净流出 **275 只(5.4%)**。

### 3. AI 事件映射的可重复性：**概率性，不是确定性**

固定 4 条事件 × 4 只标的，每只跑 5 轮（输入完全固定）：159586 计算机ETF ✅ / 000333 美的 ✅ / 600779 水井坊 ✅ / **600941 中国移动 3 轮不同 ❌**。

深挖（同一 prompt 跑 8 轮）：
- 方向分布：**利好 6 / 不确定 1 / 判为完全不相关（空数组）1**
- **8 轮给出 8 个互不相同的理由**："降低电耗成本"（利好）/ "**或推高资本开支**"（不确定）/ "与公司无直接关系"（不相关）

→ **8 轮里 6 次一致看起来还行，但有 2 次给出不同结论，其中 1 次是完全漏报。往前加"确定"是自欺欺人。**

**四等级框架（已实现）**：
| 等级 | 含义 | 判定方式 | 可复现性 |
|---|---|---|---|
| A | 直接受益主体（公告正文点名该股） | 代码 | 最高 |
| B | 强映射（事件板块 ∩ 个股概念**精确命中**） | 代码 | 完全可复现 |
| C | 弱映射（仅同行业或边缘业务，需多级传导） | 代码+AI | 部分 |
| D | 语义推测（无落到收入/成本/订单的路径） | 纯 AI | 会变 |

**核心设计：等级由匹配到的证据决定，不听 AI 自评**（怕 AI 讨好倾向把"间接"说成"直接"）。

**实测等级自动分化（最有说服力）**：同一事件「Lambda 拟在美建 330 亿美元数据中心」→ **000333 美的 B**（`精确命中:数据中心(AIDC)；模糊命中:液冷服务器`）、**000651 格力 C**（`模糊命中:液冷服务器`）。

**给使用者的自查法（数据攒够前）**：问「**这条影响能不能落到'钱'上？**」
- 落到收入/成本/订单/产能 → 可信（"中国移动运营数据中心 → 节能改造降低电费"）
- 落到情绪/偏好/预期 → 基本是噪音（"美联储加息 → 压制风险偏好 → 利空券商"）

## 六、踩坑记录（**本会话新增 14 个，坑 12~25，务必阅读**）

> 坑 1~11 见 `docs\会话交接文档_20261104.md`。

### 坑 12：polars 批内 schema 推断 —— 列前缀全空就炸 ⭐

服务端写入路径 `backend/app/services/ext_data.py:995` 是 `df = pl.DataFrame(rows)` 一次性建表，polars 只按**批内前若干行**推断列类型。最小复现：

```python
rows = [{"symbol": f"S{i}", "v": None} for i in range(150)]
rows += [{"symbol": "S999", "v": -0.413195}]
pl.DataFrame(rows)   # → ComputeError: could not append value: -0.413195 of type: f64 to the builder
```

不需要类型不同，只要**列在批内前缀全空、后面才有值**就炸。本次触发列是 `se_chg_pct` / `goodwill_ratio_qoq`。
**解法**：按「非空字段指纹」分组再切批 —— `sig = tuple(sorted(k for k, v in r.items() if v is not None))`，同指纹才进同一批。`fetch_batch2.py` 的 `ingest()` 已内置。

### 坑 13：akshare 的 `Push2RateLimitError` 是**误报** ⭐最坑

真因是本机 `HTTPS_PROXY=http://127.0.0.1:7897` 处理 push2 时**直接断开连接**，akshare 把 `ProxyError: RemoteDisconnected` 包装成了限流提示 —— **等多久都没用**。
**解法**：`s = requests.Session(); s.trust_env = False` 直连。行数随之从 5,302 → **5,927**（原 5,302 是被截断的）。

### 坑 14：AI 生成的标题每次都不同 → 去重失效

同一条新闻会变成"算力通信基础设施节能降碳改造" vs "重点行业与算力设施节能降碳改造"。
**修正：去重 key 必须基于原文** —— `key_of(sym, src, direction)` = `md5(f"{sym}|{_norm_title(src)}|{direction}")[:16]`。

### 坑 15：DSH 文件沙箱拒绝子进程写入 `tick-stock-panel/data/`

实测 `PermissionError: [Errno 13] Permission denied`；即便 Windows ACL 允许、pwsh 原生 `Add-Content` 正常，**从 python 里再起 pwsh 也被拒**。
**解法：职责分离** —— python 只把 JSONL 打到 stdout（`===ALERTS_JSONL_BEGIN===` / `===ALERTS_JSONL_END===` 包裹），由**直接执行**的 `policy-radar.ps1` 负责落盘。

### 坑 16：`stock_individual_notice_report(security=...)` 实际返回全市场公告

实测 522 行 / 918 行。必须本地按代码过滤。改为拉 `stock_notice_report(symbol="全部", date=今天)` 再过滤。

### 坑 17：财联社「标题」大量为空，正文在「内容」字段

只读标题会把政策条目**全丢掉**。`_norm()` 已在标题为空时用内容前 60 字兜底。
另：**行政性公告淹没信息**（业绩说明会/投资者关系活动记录表/股东大会资料）→ 加类型白名单 `ANN_TYPE_KEEP` + 标题黑名单 `ANN_TITLE_DROP` 双重过滤。

### 坑 18：`alerts.jsonl` 只保留 7 天

`alert_store.MAX_DAYS = 7` / `MAX_RECORDS = 5000` / `PRUNE_EVERY = 20`。而 T10 需 10 个交易日 → **光靠 alerts 永远攒不出完整样本**，台账必须独立持久化。

### 坑 19：系统 `/api/overview/market` 的 breadth 是**盘中快照，不是收盘** ⭐

实测 11-04：系统显示 up 1665 / down 3746、中位 **-0.69%**；数据湖自算 up **4666** / down 778、中位 **+1.88%**。
查 `quote_status` 见 `market_phase: "morning_final"` → 那是**上午收盘**快照。
**结论：台账基准一律用数据湖自算。**

### 坑 20：ETF 日 K 比股票滞后一天

实测 11-04 股票有、`kline_etf_enriched` 最新只到 11-03。

### 坑 21：`load_calendar` 的展开窗口是**从 asof 的上个月往「后」推**
