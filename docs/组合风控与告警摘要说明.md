# 组合风控与告警摘要说明

本文说明两件事的落地口径：**① 仓位与整体风险控制**（`portfolio_risk` / `risk` API / `PortfolioRiskPanel`），**② 告警「少而重要」**（`alert_digest` / `alerts/digest` / `AlertDigestPanel`）。

两条需求共享同一条红线：**没有真实数据就不假装分析过**。全文的「诚实边界」段落都是实现约束，不是免责声明。

---

## 一、仓位与整体风险控制

### 1.1 解决的问题

单笔仓位上限解决不了「十只票同属一个行业」：每笔都在上限内，组合却极度集中。而且「持有 10 只」不等于「分散成 10 份独立风险」——它们可能共享同一个概念故事，也可能高度相关。

所以报告不是只报一个数，而是**七个角度同时给读数**，每个读数都标明它依赖什么数据。

### 1.2 七个块（`app/services/portfolio_risk.py`）

| 块 | 函数 | 回答什么 | 关键口径 |
|---|---|---|---|
| 行业集中度 | `industry_concentration` | 最大行业占比、HHI、有效行业数 | 同花顺**二级**行业（`ext_hy_ths`）；缺行业计入 `unclassified`，不合并 |
| 主题重复暴露 | `concept_exposure` + `build_concept_clusters` | 多只票共享同一概念 = 同一个风险驱动 | `ext_gn_ths` 分号拆标签；先按覆盖率剔除通用标签，再把近义标签归并 |
| 相关性 | `correlation_matrix` / `correlation_summary` | 平均相关、最高相关对、有效独立注数 | 只用**共同交易日**；重叠 < 20 天给 `None` 不硬算 |
| 单笔风险 | `per_position_risk` | 每只票对组合的风险贡献 = 权重 × 潜在回撤 | 排序后给出最该减的那一笔 |
| 整体回撤预算 | `drawdown_budget` | 压力回撤 vs 预算，超了给削减建议 | 是**配置约束**，不是预测 |
| 情景冲击 | `scenario_impact` | 单只跌 10% / 20%，账户掉多少 pp、多少钱 | 线性近似：其余持仓不动、不含相关性放大 |
| 买入前模拟 | `simulate_buy` | 买入后集中度/回撤预算变成什么样 | before/after 同一套函数，可比 |

### 1.3 五个必须知道的口径

**① 通用概念标签必须先剔除。**
`ext_gn_ths` 里 `融资融券` 覆盖 3893 只（约 70% 全市场）、`深股通` 1895、`沪股通` 1646 —— 它们是**制度/通道属性**，不是主题。不剔除的话任意两只票都"共享三个概念"，这个面板会永远报警，等于没信息。

实现：`DEFAULT_CONCEPT_MAX_COVERAGE_PCT = 0.25`，覆盖率超过 25% 的标签进 `excluded_generic`（面板可展开看剔除了什么），剩下只保留**被 ≥2 只持仓共享**的。

覆盖率的分母用**概念表覆盖的标的数**（`len(concept_map)`），不是"覆盖最多的那个标签的计数"——后者在概念表只覆盖部分标的时会失真。

**② 近义标签要归并，但归属歧义的不许硬并。**
同花顺的标签是多层级的，同一批票被打了近义的一串。实测包含度：`人形机器人`→`机器人概念` 86%、`AI应用`→`人工智能` 81%、`AI智能体`→`人工智能` 83%、`存储芯片`→`芯片概念` 93%、`减速器`→`机器人概念` 76.9%。

不归并的话，持仓里 3 只机器人票会被拆成「机器人概念 2 只」「人形机器人 1 只」，每条都不够集中 —— **真实集中度被两条一起隐瞒了**。

`build_concept_clusters` 的判定：

| 规则 | 阈值 | 为什么 |
|---|---|---|
| 只看样本够的标签 | `coverage >= 30` | 太冷门的标签两三只票重叠就 100% 包含 |
| 父必须更大 | `\|parent\| > \|child\|` | 平级互含会来回并 |
| 认父门槛 | 包含度 `>= 0.75` | 实测同义标签都在 0.81~0.93，0.75 能收下又不放进只沾边的 |
| 归属歧义 | 第一父与第二父差 `< 0.10` | 实测 `AI视频` 对 `AIGC概念` 88.0%、`人工智能` 85.3%、`AI应用` 84.0% —— 并到任一条，另外两条的成员数凭空消失 |
| 通用标签 | 覆盖率 `> 25%` | **既不做子也不做父**（第一版漏了这条，`融资融券` 把所有标签都"包含"了） |

归并结果在面板上以「（含 人形机器人、减速器）」写出来，折叠区另有「近义标签已归并 N 组」「M 个标签横跨多个概念，未强行归并」，limitation 明写「归并依据是标签之间的标的包含度，**不是语义理解**」。

实测账户效果：`机器人概念` 从「减速器 4 只 39%」变成 **6 只 59%（含人形机器人、减速器）**、`人工智能` 3 只 28.5%（含 AIGC概念/AI应用/AI智能体/多模态AI/数据要素/虚拟数字人）—— 这是**更接近真实风险暴露**的数字。

**③ 权重分母是账户权益，不是持仓市值和。**
账户口径（`normalize=False`）下权重合计 < 1 是**正常的**：说明有现金没投。这里不能归一化，否则"3% 现金"会被隐藏成"满仓"。

实测某账户：权益 1,000,000.01、市值 971,208.55、现金 28,791.46 → `invested_ratio = 0.9712`、`cash_ratio = 0.0288`。若误用归一化，现金比例永远看不到。

调用方自报权重（`normalize=True`）时才归一化，因为那时权重的语义只是相对比例。

**④ 波动率与回撤必须逐标的算，不能用共同交易日。**
`load_daily_returns` 只保留所有标的都有行情的日期，这对**相关性**是必须的，但对"单只票自己跌过多少"是**错的**：会造成「多买一只票 → 共同日期变少 → 其它票的历史回撤跟着变」，买入模拟的 before/after 就失去可比性。

实测教训：第一版复用共同交易日，`simulate_buy` 的 `before.stressed = 17.0814` 与直接调 `build_portfolio_report` 得到的 `16.5895` 差了 0.49pp。改用 `load_price_series`（逐标的）后两者完全一致。

**⑤ 没有任何潜在回撤时，用历史实现最大回撤兜底，并写明口径。**
原来「潜在回撤」只能由调用方传，而前端从来没传 → 单笔风险与回撤预算整块是空的，用户看到"组合风险已评估"其实什么都没算。

现在 `symbol_drawdown_stats` 用过去窗口内的**实际最大回撤**做代理，limitation 明确写「是历史实现值，不是未来损失上限」。窗口内数据不足 20 天的标的**不给数**（宁可缺，不编）。

### 1.4 API

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/risk/portfolio?account=` | 账户实际持仓报告。额外附 `account_name/account_equity/account_cash/account_market_value/total_pnl`、账户级 `max_drawdown`/`current_drawdown`、`benchmark`（000300.SH 对比与超额） |
| GET | `/api/risk/portfolio?symbols=` | 观察口径（自选清单），返回 `basis=watchlist_observation` 与警告 |
| POST | `/api/risk/portfolio` | 调用方自报权重 |
| POST | `/api/risk/buy-simulation` | 买入前模拟。`account` 与 `holdings` 二选一；`new_weight_pct` 是**买入后占权益%**，不是占现有持仓% |

`_account_nav_risk` 用 `paper.load_nav` 算账户级峰谷回撤，并用 nav 行里的 `benchmark_close` 算基准对比（≥2 个有效点才算，否则给 `nav_limitation` 文案而不给 0）。

**`max_drawdown` 是历史（已经发生的），`drawdown_budget` 是压力假设（配置约束）** —— 字段名分开，不要混读。

### 1.5 买入模拟返回什么

```json
{
  "new_symbol": "600941.SH",
  "new_weight_pct": 10.0,
  "cash_weight_before_pct": 2.88,
  "over_cash": true,
  "before": { "stressed_drawdown_pct": 16.5895, "budget_usage_pct": 110.6, ... },
  "after":  { "stressed_drawdown_pct": 17.1585, ... },
  "deltas": { "stressed_drawdown_pct": 0.569, ... },
  "worst_case_loss": -171585.0,
  "warnings": [...],
  "limitations": [...]
}
```

- `worst_case_loss = -equity × after.stressed_drawdown_pct / 100`，前端标明「按压力回撤 X% 估算，不是预测」。
- `over_cash=true` 时 limitation 写「差额必须来自卖出其它持仓，本模拟未替你决定卖哪只」——这是刻意的：这个功能不替用户做卖出决策。
- `deltas` 只覆盖 6 个可比指标（`top_industry_share / effective_industries / effective_bets / max_position_weight / stressed_drawdown_pct / budget_usage_pct`）。

**实测（真实账户 10 只持仓）**：压力回撤 16.59% vs 预算 15% → `budget_usage 110.6%`、`over_budget=true`、建议削减只点了一只（300299，减 6.83pp）。主题 Top3：减速器（4 只 / 39.03%）、人民币贬值受益（3 只 / 29.57%）、人形机器人（3 只 / 29.03%）。

### 1.6 前端

`frontend/src/components/signals/PortfolioRiskPanel.tsx`：
- `PortfolioRiskPanel`：传 `account` 走账户口径（`api.portfolioRiskByAccount`）并 `autoRun`；不传则走调用方自报权重，此时必须显式声明"这不是实际持仓"（`warnObservation`）。
- `BuySimulationCard`：默认不请求，点「模拟」才发；变差的行标红（`higherIsWorse = !key.startsWith('effective_') && key !== 'top_concept_symbols'`）；超过现金占比给黄条。
- 现金 < 5% 给红色警告：「几乎没有缓冲——一次深回撤后没有加仓能力，也无法应对取现。」

调用点在 `frontend/src/custom/paper/Page.tsx`（持仓页「组合风险」区块）。

## 二、告警「少而重要」

### 2.1 问题

真实数据 `data/user_data/alerts.jsonl` 285 条告警里：

- 政策类 100 条，只涉及 **11 个不同标的**，同一标的最高 21 条 —— 不是同文转载（同一 message 重复只有 1 条），而是**同标的被不同事件反复关联**。
- 字段覆盖极稀疏：`mapping_level` 只有 58/285 条有值、`directness` 46、`impact_path_text` 45。
- 前端**完全不读** `mapping_level` / `directness` / `verification` / `impact_path_text` / `published_at` / `source_name` → 用户要的「直接还是推断 / 来源日期 / 影响渠道 / 是否需动作」在产品里根本没显示。

结果就是：条数驱动，弱关联推断和公司公告长得一样。

### 2.2 四档（`app/services/alert_digest.py`）

| 档 | 含义 | 推送 | 视觉 |
|---|---|---|---|
| `must_know` | 公司自身事件且核实状态为 fact/evidenced；或命中用户设定条件 | ✅ | 红 |
| `worth_notice` | 公司自身事件但核实状态较弱；或行业事件但映射属直接（A/B） | ✅ | 黄 |
| `theme_hint` | 推断关系（C/D）或关系未判定 → **主题线索** | ✅（默认折叠） | 最淡 |
| `background` | 宏观/市场级信息，非个股事件 | ❌ 即使全新也不推 | 灰 |

推送过滤：`_keep = hit_rule or risk_changed or (is_new_fact and tier != background)`。

**为什么 background 全新也不推**：推它们就等于回到条数驱动，用户会重新开始忽略通知。它们仍进 `suppressed` 列表（可查看），只是不主动占注意力。

`grade` 判定顺序：宏观且非自身 → background；推断且非自身 → theme_hint；关系未判定且非自身 → theme_hint；自身+fact → must_know；自身其它 → worth_notice；非自身且 A/B → worth_notice；其余 → background。

### 2.3 每条提醒回答四问

```
what_happened: { title, event_date, published_at, sources, source_count,
                 verification, verification_label, alert_count, missing }
why_related:   { symbols, relation: direct|inferred|unknown, relation_label,
                 relation_reason, mapping_levels, direction }
impact_channel:{ channel_text, channel_kind, available, note }
action:        { needs_action, label, hint }
```

**三条诚实边界（写死在实现里）**：

1. `impact_channel`：采集侧没给 `impact_path_text` 就写"未提供"并给 `note`，**不代填传导路径**。
2. `why_related`：`directness` / `mapping_level` / 文案弱关联三字段全缺时标 `unknown`，**不默认"直接"**。理由：285 条里 `mapping_level` 只有 58 条有值，默认直接会把 227 条未知伪装成事实。
3. `missing` 字段列出采集侧缺了哪些字段，前端显示为「采集侧缺字段：X、Y —— 这几项没显示是没数据，不是没问题」。

用户举的那个例子就是活样本：宏柏新材「上海推动大兆瓦海上风机批量应用」（605366.SH）—— `mapping_level=C`、`mapping_level_desc=弱映射（仅同行业或边缘业务，需多级传导）`、`mapping_basis=模糊命中:风电；AI判定:间接`、`directness=间接`、`verification=inferred`、`impact_path_text=上海推动大兆瓦海上风机批量应用 → 风电叶片用玻纤/复材需求增加 → 宏柏硅烷偶联剂需求受益`。它分档为 `theme_hint`，**默认折叠**，需要主动展开才看，而公司减持公告是 `worth_notice`。

### 2.4 去重与「只说新事实」

- `dedupe`：`_skeleton` 只保留 `isalpha()` 字符取前 24 位做 md5（数字/标点会变、措辞一致）。保留 `last_ts` 最大者并累计 `repeat_count`、记 `superseded_ts`。
  去重键**分两种**：
  - 自身事件（公司公告）：`标的集合 + 标题骨架 + 方向` —— 两家公司都发「股东减持公告」是两件事。
  - 环境事件（行业/宏观）：`标题骨架 + 方向`，**不含标的** —— 同一条政策被采集侧挂到 3 只 ETF 上是同一件事的三条匹配。合并后把标的并起来（`syms=159682.SZ,159586.SZ,000333.SZ`），用户看到"这条影响我哪几只"，而不是同一句话重复三行。

  实测效果：42 组 → **32 组**。「字节跳动考虑扩大巴西数据中心项目」从 3 行变 1 行（`repeat_count=3`）。
- `prior_state`（`state_from_digest` 产出）：`verification` 或 `mapping_level` 变化 → `risk_changed=true` + `change_note="核实状态升级：inferred → reported"`。**已看过的事件，只要风险变了仍然推。**
- `watch_rules`：symbol + type 都匹配（空串当通配）→ 强制升到 `must_know` + `action.label="你要求提醒"`。

**状态键 `state_key` 与 `event_group_id` 是两个字段。** `event_group_id` 是采集侧的事实（没归组就是 `null`）；`state_key` 是本地状态坐标，没有前者时由去重键派生（`local:<md5>`）。只认 `event_group_id` 会让未归组的条目——实测有 1 条（美的公告）——永远记不住、天天重报。`state_from_digest` 优先用 `state_key`。

**「已看过」是落盘的**（`app/services/alert_seen.py` → `data/user_data/alert_seen.json`），不是只活在一次请求里。曾经的做法是 `since_ts` 时间切分，刷新页面/换设备就全忘了 —— 所有旧事实第二天早上又重新报一遍，用户马上回到"每天都一样、于是都不看"的状态。

四条设计约束（都不是随手选的）：

| 约束 | 理由 |
|---|---|
| 键是**事件组**不是标的 | 同一只票一天可能挂 20 条不同事件；按标的记会把明天的新公告一起吞掉。未归组时用 `state_key`（标题骨架 + 方向 + 自身事件的标的），仍不是"按标的" |
| 只记状态不记内容 | `alerts.jsonl` 已是正文唯一真相源，再存一份会在不一致时无从判断谁对 |
| 写失败不影响读 | 状态文件唯一作用是"少报一点"，异常时退化成"全部当新事实"而不是接口 500 |
| 有上限 | `MAX_GROUPS=5000` 按 `last_seen` 淘汰、`MAX_AGE_DAYS=30` |

`first_seen` 永远保留最早一次（用来回答"这条跟了多久"），`last_seen` 取最新（只用于淘汰）；`verification`/`mapping_level` 一律用**本次**的值 —— 留旧的会让风险变化永远检测不到。

**关键：只有 `ack=true` 才落盘。** 前端 60 秒轮询一次，若读接口自动标已看，第一次拉完就把所有条目标成看过，用户根本没机会看到。所以面板底部有一个显式按钮「这些我看过了（N 条，下次不再提醒）」。

ack 记的是**本次展示的条目**（受 `max_items` 截断），不是全部新事实 —— 用户点的意思是"屏幕上这 N 条"。所以返回里会明写「本次展示的 6 条已记为「已看过」（累计 6 条）…被 `max_items` 截断的其它条目仍会出现」。实现上 `state_from_digest(digest, include_suppressed=False)`，把用户没看见的 `suppressed` 条目排除在状态之外。

### 2.5 三轮真实数据校准（踩过的坑，别再踩）

1. **`type` 实际是「来源_分类」格式**，不是英文枚举。实测取值：`policy_政策` 52 / `policy_产业` 24 / `policy_公告` 9 / `policy_地缘` 7 / `calendar_domestic` 8 / `paper_fill` 62 / `fill` 62 / `auto_order` 60。第一版只比英文枚举 → 「宏柏新材:股东减持公告」被判成 `theme_hint`。修：补中文分类词（公告/业绩/减持/增持/回购/分红/解禁/质押/诉讼/重组/停牌/复牌/问询/监管/退市），判定时同时比整串与 `raw.split("_")` 各部分，另加标题关键词兜底。

2. **不能靠「只关联 1 个标的」判断自身事件**。加了这条兜底后「欧元区通胀」「9月新增新能源发电项目」「央行第三批互换便利」「LPR 报价」全被判成公司自身事件。修：新增 `_MACRO_MARKERS` 排除（央行/LPR/社融/M2/M1/统计局/财政部/证监会/发改委/国务院/美联储/欧盟/欧元区/加息/降息/降准/互换便利/国债/汇率/通胀/CPI/PMI/GDP/关税/制裁/贸易救济）。随后「字节跳动扩大巴西数据中心」「前三季度老旧小区改造1.6万个」仍误判 → **彻底删掉**这条兜底。

   理由写进 docstring：**标的数量反映采集匹配宽度，不是事件主体。**

3. **政策会议级表态要进宏观词表，但部委名不能进**。实机发现「国常会要求完善资本市场稳市机制」被挂在个别标的上、判成 `theme_hint` 列出，但它是市场级表态、不是那家公司的事。修：`_MACRO_MARKERS` 追加 `国常会 / 国务院常务会议 / 政治局 / 中央经济工作会议 / 两会 / 中央金融工作会议`。

   **刻意不加具体部委名**（金融监管总局/银保监会/商务部/工信部/国家能源局/海关总署/外汇局/国资委 都不加）：因为「某公司被证监会处罚」「XX被交易所问询」这类标题里的部委名恰恰是公司自身事件，误排除会把必须知道的公告降级成背景信息。

   同理新增 `_COMPANY_ACTION_MARKERS`（减持/增持/回购/业绩预告/业绩快报/年报/季报/分红/解禁/质押/诉讼/问询/停牌/复牌/立案/处罚/警示函/监管函/退市/被调查），宏观排除改判为：

   ```python
   if any(_MACRO_MARKERS) and not any(_COMPANY_ACTION_MARKERS):
       return False   # 不是自身事件
   ```

   这样「某公司被证监会立案调查」命中"证监会"但也被"立案"命中 → 仍然算自身事件。**刻意不含「公告」「股东」**：`证监会公告〔2026〕1号` 是政策文件，不是公司公告；用宽词会让政策面内容冒进「值得留意」。

4. 校验方法：每次改完都拿真实 285 条重跑，逐条看 605366.SH 那四条的分档是否符合直觉。

   改完宏观词表后的实机验证：`/api/alerts/digest?max_items=10` 的 `by_tier` = `must_know 1 / worth_notice 1 / background 0 / theme_hint 8`，「国常会」那条已不在 items 里（落入 background 被过滤，但仍可从 `suppressed` 查看）。

### 2.6 API 与前端

`GET /api/alerts/digest`（`app/api/alerts.py`）参数：`days` / `limit` / `symbol` / `kinds` / `max_items`(1~200，默认20) / `use_seen`(默认 true) / `ack`(默认 false) / `since_ts` / `watch_symbol` / `watch_type`。

三种时间基准的优先级：**`since_ts`（显式）> 落盘状态（默认）> 无状态（全部当新事实）**，实际用了哪一路写在返回体的 `filters.state_source`（`since_ts` / `persisted` / `none`）。

返回体追加：`只查最近 {days} 天（存储侧上限 {MAX_DAYS} 天）；更早的告警不在本次结果里，不代表没发生过`；非 ack 时再追加 `「已看过」只在调用方传 ack=true 时才更新；重复请求会重复列出同一条新事实`。

> 实测坑：605366.SH 的减持公告是 9.3 天前，而 `alert_store.MAX_DAYS = 7`，默认窗口查不到 —— 所以这条 limitation 是必要的，不然用户会以为公告消失了。

前端 `frontend/src/components/monitor/AlertDigestPanel.tsx`：
- 四档视觉分级，`theme_hint` **最淡**且默认不显示，需点「显示 N 条主题线索（弱关联，仅作参考）」。
- 只有 `must_know` 默认展开，其余档点标题展开。
- 头部显示「需要知道 N / 值得留意 N / 线索 N」与「按事件去重 · 只说新事实」。
- 底部按钮「这些我看过了（N 条，下次不再提醒）」→ `ack=true`，成功后 invalidate 重拉。失败显示「记录失败，可重试」，**不假装成功**。
- 面板**不出现任何买卖建议字眼**（`买入建议`/`buy_score`/`sell_score`/`recommendation`/`评级`，有测试锁死）。

`kinds` 只接受**事件类别**（`policy_news`/`trading`/`signal`/`other`），传 `kinds=policy` 会 422 —— 想按来源（policy_radar/policy_calendar）过滤用 `source` 参数。

实测：285 条 → `total_groups=88 / after_dedupe=82`。605366.SH 四条依次为 `worth_notice`（减持公告）、`background`（欧元区通胀）、`theme_hint`（上海海上风机）、`theme_hint`（9月新能源发电）。

## 四、刻意没做的事（以及为什么）

1. **没有真实持仓时不做"完整组合分析"**。观察口径（自选清单）明确标 `basis=watchlist_observation` 并给警告条：「这里把自选清单等权当成组合，它不是你的实际持仓」。等权不是建议配置比例。
2. **不替用户决定卖哪只**。买入模拟超过现金占比时只报 `over_cash=true` 与差额来源，不给"卖 A 买 B"的建议。
3. **不把「历史最大回撤」说成「未来最多亏多少」**。limitation 写明是历史实现值。
4. **不自动把告警升档**。分级只用于排序与措辞，不产生买卖信号；`watch_rules` 是**用户显式设定**的，不是系统猜测。
5. **不合并宏观信息进个股提醒**。宏观进 `background`，即使全新也不主动推。
6. **ETF 仍按自身持仓展开，不做行业穿透**（组合层面的穿透需要 ETF 成分数据，本地没有）。
7. **读接口不改「已看过」状态**。只有用户点「这些我看过了」才 `ack=true` 落盘 —— 否则 60 秒轮询会把用户永远看不到的东西全标成看过。
8. **不在归并上"尽量并"**。归属歧义（多个父的包含度只差几个百分点）一律不并，只列出来说明"这几个概念在底层是同一批票"。并错的代价是让用户以为某条主线只占 39%，而实际是 59%。

## 五、遗留

- 概念归并只做**标的包含度**，不做语义理解。它能把「人形机器人」并进「机器人概念」，但推不出「算力」和「AIGC」是同一件事 —— 那需要概念层级或相关性数据。歧义标签（如 `AI视频` 同时落在 `AIGC概念`/`人工智能`/`AI应用`）宁可放着不并，并在面板上列出来。
- 情景冲击是线性近似，不含相关性放大。做「市场整体跌 10%」需要因子模型，不在本轮范围。
- 账户级 `max_drawdown` 依赖 `paper.load_nav` 的日频记录，账户新建时样本很短（实测某账户只有 3 天），此时基准对比没有意义 —— `nav_limitation` 会说明，但不会阻止展示。
- 「已看过」状态现在能记住未归组条目（`state_key`），但同一事件**不同措辞**仍会各算一次：「字节跳动考虑扩大巴西数据中心」与「字节跳动考虑扩大巴西数据中心项目」仅差两个字，骨架取前 24 个字符后落成了两个不同的 md5。要真正归一需要采集侧提供事件实体或标题做规范化，不在本轮范围。
