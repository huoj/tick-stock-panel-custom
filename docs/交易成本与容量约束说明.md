# 交易成本与容量约束口径（P0 修复说明）

> 背景：同一策略在三个入口给出三种净收益 —— 回测 API 默认**零印花税**、
> 前端默认 **0.1%（真实值的 2 倍）**、模拟盘 0.05% 却**不区分品种**（ETF 也被扣）。
> 同时回测可以在冷门股上无限成交，容量不受任何约束。
> 本次把这些全部收口到单一事实源，并补上容量约束与原始价过滤。

## 一、单一事实源：`backend/app/fees.py`

所有费率默认值、品种差异、最低佣金只在这里定义一次；回测、模拟盘、因子回测
全部委托它，不再各自硬编码。

### 制度性默认值（截至 2026）

| 项目 | 值 | 作用范围 |
|---|---|---|
| 佣金 | 万 2.5（0.00025） | 双边 |
| **最低佣金** | **5 元/笔** | 逐笔，仅绝对金额层 |
| 印花税 | 0.05%（0.0005） | **仅卖出、仅股票** |
| 过户费 | 0.001%（0.00001） | 双边、仅股票 |
| 滑点 | 5 bps | 双边（与规模无关的近似） |

**免税是法定事实，不可配置**：`asset_type ∈ {etf, fund, lof, bond, index}`
时印花税与过户费**无条件归零** —— 即使调用方显式传了税率。这正是此前
"ETF 每次卖出被多扣 0.05%"的来源。

### 两个解析口径

`resolve_cost_model()` 用 `fees_pct` 是否为 `None` 区分：

| 触发条件 | 口径 | 含义 |
|---|---|---|
| `fees_pct is None`（**默认**） | **现代全项口径** | 佣金万2.5 + 印花税按品种 + 过户费仅股票 + 最低佣金 5 元 |
| `fees_pct` 显式给出 | **历史一价全包口径** | `fees_pct` 含全部成本；不再加印花税/过户费，**也无最低佣金** |

保留第二个口径是刻意的：`fees_pct` 这个字段诞生时的语义就是"一价全包"，
既有测试与历史回测里 `fees_pct=0` 是**字面意义的零成本**。把它悄悄解释成
"佣金为 0 但印花税照收"会改变所有历史回测的可比性。

要在历史口径上收印花税，必须显式传 `stamp_tax_pct`。

## 二、三处入口的实际行为

### 1. 回测引擎（`app/backtest/engine.py`）

`MatcherConfig` 的成本字段全部默认 `None` → 走现代全项口径。

```python
MatcherConfig()                        # 佣金万2.5 + 印花0.05% + 过户 + 最低5元
MatcherConfig(asset_type="etf")        # 佣金万2.5, 印花0, 过户0
MatcherConfig(fees_pct=0)              # 字面零成本 (历史口径)
MatcherConfig(stamp_tax_pct=0.0)       # 股票但明确不要印花税
```

账目分两层，不要混用：

| 层 | 用途 | 是否含最低佣金 |
|---|---|---|
| `cost_model.buy_amount()` / `sell_amount()` | **实际账目**（`entry_value` / `exit_value` / `cash`） | ✅ 含 |
| `buy_cost_pct()` / `sell_cost_pct()` | 事前估算、手数预分配 | ❌ 不含 |

**独立候选模式例外**：该模式按固定 100 股归一比较信号质量，不代表任何真实
仓位规模 —— 最低佣金 5 元落在 1000 元名义仓位上等于 0.5%，会彻底污染评估。
因此该路径只用百分比口径（`engine.py` 两处 `shares = 100.0` 的账目）。

### 2. 模拟盘（`app/strategy/paper.py`）

`buy_fee` / `sell_fee` 新增 `asset_type` 关键字参数（默认 `"stock"`，保持既有
调用方语义）；`_fill_order` 与下单预检都传入订单的 `asset_type`。
另提供 `account_cost_model(acc, asset_type)` 把账户设定费率与品种差异合成
一个 `CostModel`。

### 3. 因子回测（`app/backtest/factor.py`）

`_round_trip_cost()` 委托 `fees.resolve_cost_model(...)` 取
`round_trip_cost_pct()`；分层回测按等权组合收益率扣减，没有单笔金额概念，
因此 `min_commission=0`。

### 4. API 与前端

| 位置 | 改动 |
|---|---|
| `BacktestRequest` / `StrategyBacktestRequest` / `FactorBacktestRequest` / `FactorBatchRequest` | `fees_pct` 默认改为 `None`（→ 现代口径）；新增 `transfer_fee_pct` / `min_commission` |
| `/strategy/stream`、`/optimize-robust/stream`、`/walkforward/stream` | 同上，并把新字段并入 `_OPT_BT_FIELDS`（参与缓存键） |
| `_make_job_key` | `fees_pct=None` 用稳定哨兵 `-` 参与哈希，避免与用户真填值混淆，也避免 stream/cancel 两端算出不同 key（停止按钮失效） |
| 前端回测页 | 佣金/印花税输入框**默认留空**（= 后端制度默认），占位符显示 2.5 / 0.5；留空即不传该字段 |
| 前端因子页 | 佣金默认留空；填了则按"一价全包"理解 |

## 三、容量约束：`max_participation_pct`

### 为什么需要

没有它，50 万的账户和 1 亿的账户跑同一策略会得到几乎一样的曲线 ——
回测可以在日成交额 2000 万的冷门股上一次打进 100 万而不受任何惩罚。
**这是"回测好看"与"实盘能做"之间最大的缺口。**

### 规则

```
单笔可成交股数上限 = 标的当日成交额(amount) × max_participation_pct ÷ 成交价
                     向下取整到 100 股
```

默认 `0.10`（10%）。`None` 或 `0` = 不约束（纯研究口径，与现实不符）。

### 两处截断点

- `_simulate_portfolio_matrix`（矩阵路径）：`shares` 算出后按
  `matrix.amount[time_id, asset_id]` 截断；
- `simulate_portfolio_legacy`（面板路径）：按 `panel["amount"]` 截断。

截断后若不足一手，记 `buy_participation` 并跳过该标的。

### 无法评估时的处理

成交额缺失（指数量表、极早期分区、停牌）→ `_capacity_lot_cap*` 返回 `None`，
引擎记 **`buy_participation_unknown`** 并放行。不静默伪造容量数据，也不
因为数据缺失就拒绝全部交易 —— 计数暴露在 `stats.execution` 里供审计。

### 依赖声明

容量约束需要 `amount` 列进矩阵。默认 `DEFAULT_BASIC_FILTER` 的 `amount_min`
已带上它；自定义过滤去掉 amount 界时，`_capacity_dependencies()` 会补齐
（`resolve_backtest_request_plan` 在 `build_matrix_cache_profile` 之前执行，
保证缓存键看到同一字段集）。

**独立候选模式不加容量约束** —— 该模式不做资金分配，容量无意义。

## 四、基础过滤改用原始价

### 问题

`DEFAULT_BASIC_FILTER` 有 `price_min: 3 / price_max: 300 / market_cap_min: 10e8`，
而落地表达用的是 `close`（**前复权价**）。前复权价会随之后每一次除权除息被
整体下调，于是：

- "3 元以下剔除"在 2019 年与 2026 年筛的是**不同批股票**；
- `market_cap = close × total_shares` 用前复权价算 → **历史市值被系统性低估**，
  市值门槛随时间漂移。

### 修复

两处实现统一改用餐原始价：

- polars 侧：`StrategyEngine._basic_filter_price_col()` —— `raw_close` 非空且 >0
  时用它，否则回退 `close`（不整列丢弃）；
- numpy 侧：`matrix._filter_price_matrix()` —— 同口径。

依赖声明同步：`_basic_filter_dependencies()` 在设置了任一价格界或市值界时
加入 `raw_close`，否则矩阵里只有前复权 close，改了取价也拿不到原始价。

### 验证

一只 10 送 10 后的股票：`close=10`、`raw_close=20`。旧口径在 `price_min=15`
时把它错误剔除；新口径保留。

### 实际金额核对（10 万元股票往返）

```
买费 26.00 (佣金 25 + 过户 1)
卖费 76.00 (佣金 25 + 过户 1 + 印花 50)
合计 102.00 = 0.102%   ← 旧 API 默认口径只有 0.040%，且不含印花税
ETF 同条件: 买 25 + 卖 25 = 50 = 0.050%（免印花税与过户费）
```

## 六、行为变更（需知情）

1. **不传任何成本参数的回测，结果会比以前差**。这是修复，不是回归 ——
   以前少算了印花税与过户费。
2. `fees_pct` 显式给出的调用方**行为不变**（仍是一价全包、无最低佣金）。
3. 前端佣金/印花税输入框默认留空，占位符提示默认值；留空即走后端制度默认。
4. 组合回测新增 `max_participation_pct` 默认 10% —— **大资金回测结果会下降**，
   这是容量约束在起作用。要看"无约束的理论上限"，把它设为 `null`。
5. 基础过滤的价格/市值判定改用餐原始价 —— 历史区间的候选池会变化。

## 七、仍然没做的（P1，见交易视角审视）

- 冲击成本随规模上升的建模（当前滑点与规模无关）；
- tick 对齐（`tick_size` 仍未消费，成交价可能出现 10.1234 这类盘口不存在的价）；
- 组合级约束（单票上限 / 行业上限 / 相关性）；
- 基准对比与 alpha/beta/信息比率；
- 现金分红现金流（模拟盘不处理；回测用 qfq 隐含红利再投资）；
- 退市标的纳入（存活者偏差）。
