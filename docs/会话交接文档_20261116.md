## 三、关键根因 / 决策（下一位最容易踩的）

1. **`account.json` 现在是 `{"cash": null}`，用户还没重填现金**。后果：`cash_ratio=0.0`、`invested_ratio=1.0`，组合风控看起来**像满仓**。这是如实披露（`weight_basis` / limitations 都写了），**不是 bug**。要让用户去「持仓总览 → 现金设置」填一次。
2. **`/api/health` 返回 200 但 body 是 HTML**。任何未定义的 `/api/*` 路径都被 SPA 回退接走 → **不能用状态码判断接口是否存在**，看 body 是否 JSON。
3. **`run-local.py` 无 reload**。改后端必须重启 3018；改前端必须 `pnpm build` + `Ctrl + F5`。本会话两次「改了看不到」都和这条有关。
4. **`_replay_up_to` 返回 dict 子类，迭代只给 key**。`holding_ledger._PositionResult` 重写了 `__getitem__` / `__contains__` / `get`，但**没重写 `__iter__` / `values()`** → 遍历持仓行必须 `.values()`。
5. **NaN 会穿过所有范围比较**。`NaN < 0`、`NaN > MAX`、`NaN <= 0` 全是 False。凡「数值范围校验」都必须先 `x != x` 拦 NaN，否则会落到后面 `int(x)` 之类的语句炸出英文内部错误。
6. **负成本不能当现价**。放开负成本录入后，任何「取不到行情就按 `avg_cost` 兜底当价格」的写法都会算出**负市值**。正确做法：`last = avg_cost if avg_cost > 0 else 0.0`，且未取到行情时**盈亏必须归零**而不是「0 − 负成本」。
7. **`PortfolioRiskPanel.tsx` 是共享组件**，`frontend\src\custom\paper\Page.tsx:2344,2351` 也挂它。改它必须跑 `RiskPanels.test.tsx`，且保 `600001.SH ↔ 600002.SH` 原串、`-6.00pp` 数值、`17.16 万` 子串三条约束。
8. **`report["limitations"]` 有白名单断言**（`backend\tests\test_portfolio_risk.py`），新增诊断信息一律开新键，不要塞 limitations。
9. **`symbols` 观察口径与 `source=manual` 真仓口径在 `GET /api/risk/portfolio` 上互斥（400）**。组合风控页的「导入自选」走 `POST` 等权 holdings（`basis=caller_supplied_weights`），不是 GET symbols。

## 九、本会话的方法论教训

1. **先证「页面存不存在」，再证「构建新不新」**。上期「没看到面板」的真因是页面根本不存在；本会话「改了看不到」的真因是 dist 没重建。两个方向都要查。
2. **「后端有、前端没渲染」比「算法不对」更常见**。行动卡页面 14 个字段后端算好却一个字都没渲染 —— 这类问题用 `grep 字段名 frontend/src` 命中数为 0 就能快速定位，比读算法高效得多。
3. **先看数据会不会把结论读反**。`forward_stats` 只渲染胜率，会让「1 日 67%」掩盖「10 日 33% 且跑输 27pp」——**呈现方式造成的误导，比算错更难被发现**。
4. **NaN 是所有范围校验的漏网之鱼**。`NaN < 0`、`NaN > MAX`、`NaN != 0` 全为 False，三个 bug 里有三个都和它有关（qty、cash、以及负成本兜底价）。凡做数值校验，第一行先拦 `x != x`。
5. **放宽一条校验，就要检查所有依赖它的下游**。负成本放开后，`portfolio_positions` 里「取不到行情就按成本兜底当价格」立刻算出负市值。**放开输入约束时，必须把「该字段被当作价格/分母用」的所有地方过一遍。**
