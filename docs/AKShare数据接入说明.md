# AKShare 数据桥 —— 缺口补齐说明

> 完成时间：2026-11-03
> 目的：用免费数据源补齐 TSP 缺失的 8 个数据维度
> 落地方式：TSP 扩展表（ext_data）
> 独立环境：`D:\deepseek_path\databridge`

---

## 一、为什么要独立部署

**AKShare 不是"更好的分析框架"，而是"数据获取库"。**

之前评估的 GitHub 项目（qlib / vnpy / OpenBB / hikyuu / rqalpha）都是**分析或交易框架**，本身不带 A 股基本面数据。TSP 已经具备分析能力（因子 IC、回测、扫描、AI 助手），真正缺的是数据。

**为什么放在独立环境：**

| 原因 | 说明 |
|---|---|
| 依赖隔离 | akshare 依赖 pandas/requests/bs4 等，避免污染 TSP 的 uv 环境 |
| 故障隔离 | 取数失败不影响面板运行 |
| 独立升级 | akshare 更新频繁，可单独升级 |

## 四、两个新维度的实测发现

### 发现 1：股东户数变化（筹码集中度）

| 股票 | 股东户数 | 变化 | 变化率 |
|---|---|---|---|
| **格力电器** | 501,298 | **-80,154** | **-13.79%** |
| **中国移动** | 161,308 | **-33,165** | **-17.05%** |
| 东方财富 | 988,112 | -41,255 | -4.01% |
| 水井坊 | 70,550 | -2,817 | -3.84% |
| 美的集团 | 249,414 | -2,230 | -0.89% |
| **宏柏新材** | 57,095 | **+18,505** | **+47.95%** |

**解读：**
- **户数减少 = 筹码集中**（大户/机构在收集）→ 格力、中国移动减少 13-17%
- **户数暴增 = 筹码分散**（散户在接盘）→ **宏柏新材 +47.95%**

**宏柏新材这个数据与之前的因子分析完全吻合：** 换手波动 3.87（全场最高）、三灯全红、股东户数暴增 48% —— **典型的"机构派发给散户"形态。**

### 发现 2：资产负债表的隐藏风险

| 股票 | 存货 | 商誉 | 短期借款 | 长期借款 |
|---|---|---|---|---|
| 中国移动 | 161.56 亿 | 37.69 亿 | 0 | 92.4 亿 |
| **美的集团** | 566.26 亿 | **311.47 亿** | **456.21 亿** | 186.98 亿 |
| **格力电器** | 263.76 亿 | 13.24 亿 | **807.62 亿** | 6.61 亿 |
| 长城汽车 | 401.71 亿 | 0.28 亿 | 80.84 亿 | 0.45 亿 |
| 水井坊 | 40.37 亿 | 0 | 10.61 亿 | 0 |
| 宏柏新材 | 2.69 亿 | 0 | 1.44 亿 | 3 亿 |
| 东方财富 | 0 | 29.46 亿 | 20.49 亿 | 0 |

**两个值得注意的点：**

**① 格力电器短期借款 807.62 亿**

格力账上现金 1175 亿，却借了 807 亿短期借款。这通常是**票据贴现/供应链金融**操作（低息借、高息存），不一定是财务危机。**但这么大的规模值得盯。**

**② 美的集团商誉 311.47 亿**

主要来自 KUKA 收购。**商誉是减值风险敞口** —— 如果 KUKA 业绩不达预期，会一次性计提减值，直接冲击利润。

## 六、技术踩坑记录（重要）

### 坑 1：ingest 要求每行包含全部声明字段

**现象：** 400 `第 1 行缺少字段: announce_date, avg_mv, ...`

**原因：** 服务端校验 `required = configured - {"symbol"}`，缺任一字段即拒绝。

**解法：** 每行先填充 `{k: None for k in 全部字段}`，再赋值。

### 坑 2：dtype 不一致导致"覆盖写入"

**现象：** 写入 5578 行，查询只剩 378 行（正好是最后一批的行数）。

**原因：** 整数批次推成 `Int64`、含缺失的批次推成 `Float64`，与已存文件 `concat` 报
`type Int64 is incompatible with expected type Float64`，服务端降级为**覆盖写入**。

**解法：** 所有数值字段强制 `float`（包括整数），绝不让 polars 推断成 int。

### 坑 3：symbol 为 None 导致全部折叠成 1 行

**现象：** 写入 5578 行，查询只剩 1 行。

**原因：** snapshot 模式按 `symbol` 去重 `unique(subset=["symbol"], keep="last")`。
我的 `build_rows` 因为 `symbol` 不在 SCHEMA 列表里而没赋值，**所有行 symbol 都是 None，被当成同一个 key。**

**解法：** `symbol` 单独处理，不依赖字段白名单判断。

### 坑 4：逐股接口太慢

**现象：** 新浪财务报表逐股拉取，5569 只单线程需 **105 分钟**。

**解法：** 16 线程并发 + 断点续传（跳过已有 symbol），降到 **8.7 分钟**，0 失败。

### 坑 5：snapshot 模式每只股票只能存 1 行

**现象：** 解禁 1477 条 → 只剩 1057 行；大宗交易 5844 条 → 只剩 841 行。

**原因：** snapshot 按 symbol 去重，同一股票的多条记录只保留最后一条。

**解法：** 对多事件数据改用**聚合口径**：
- `ext_unlock` → 最近解禁日 + 总市值 + 批次数
- `ext_blocktrade` → 笔数 + 总成交额 + 平均折溢价

**如需保留明细，应改用 `timeseries` 模式（按日期分区）。**

## 七、已知局限

**1. 北向资金无法补**

2024 年 8 月起交易所取消北向资金实时披露，akshare 对应接口已失效。**这是政策原因，无法绕过。**

**2. snapshot 模式下多事件数据被聚合**

解禁、大宗交易只能看汇总。要保留明细需改 timeseries 模式。

**3. 基金持股的"变动"字段可信度待验证**

实测 7 只自选股全部显示"增仓"，可能是抓取的是同一季度快照导致，**建议用前十大股东数据交叉验证**。

**4. 机构评级有系统性偏多**

6 只自选股全部是"买入"评级。**券商评级几乎不给卖出**，参考价值有限，只能看买家数相对变化。

**5. 数据依赖第三方公开接口**

akshare 底层是新浪/东财/同花顺等公开接口，**接口变更时需跟进升级 akshare**。

**6. 存货口径要注意行业差异**

白酒的基酒、地产的土地、制造的产成品，**同一指标在不同行业含义完全不同**，不能横向直接比。

## 八、补数据之后能做什么

**新增可查询的维度：**

| 问题 | 之前 | 现在 |
|---|---|---|
| 这只股票下个月有解禁吗？ | ❌ 查不到 | ✅ `ext_unlock` |
| 股东户数在增加还是减少？ | ❌ 查不到 | ✅ `ext_shareholders` |
| 股息率多少？ | ❌ 查不到 | ✅ `ext_dividend` |
| 存货/商誉/借款多少？ | ❌ 只有 12 个字段 | ✅ `ext_bsdetail` |
| 基金在加仓还是减仓？ | ❌ 查不到 | ⚠️ `ext_fundhold`（待验证） |
| 业绩预告怎么说？ | ❌ 查不到 | ✅ `ext_forecast` |
| 券商评级分布？ | ❌ 查不到 | ✅ `ext_research` |
| 有大宗折价交易吗？ | ❌ 查不到 | ✅ `ext_blocktrade` |

**这些都可在扫描器 `ext_columns` 和 AI 助手里直接引用。**

**示例：**
```
ext_columns: "ext_bsdetail.inventory,ext_dividend.yield_pct,ext_shareholders.holders_chg_pct"
```

## 九、诚实的总结

**补数据提升了"排雷能力"，不提升"预测能力"。**

新增数据能帮你回答的都是**当下的确定事实**：
- 下个月有没有解禁
- 股东户数在增还是在减
- 商誉有多大
- 股息率多少

**这些不预测涨跌，但能帮你排除明显有问题的标的。**

我们这一路的实测结论没有改变：
- 25 个策略全部亏损
- 27 个显著因子里 26 个反向
- 低估值因子 IC +0.0825，t=1.68 未达显著

**所以最有价值的用法仍然是：先排除坏标的，再谈选择。**
