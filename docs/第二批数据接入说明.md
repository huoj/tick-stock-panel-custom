## 二、字段说明

### ext_goodwill（商誉占净资产比）

| 字段 | 含义 |
|---|---|
| **goodwill** | 商誉金额（元） |
| **net_equity** | 归母净资产（元） |
| **goodwill_ratio** | **商誉占净资产比（%）← 核心排雷指标** |
| goodwill_prev / goodwill_chg | 上期商誉 / 变动额 |
| goodwill_chg_pct | 商誉变动率（%） |
| net_profit / np_yoy_pct | 归母净利润 / 同比（%） |
| se_chg_pct | 净资产变动率（%） |
| **goodwill_ratio_qoq** | **占比环比变动（百分点）** |
| **goodwill_ratio_max** | **近 4 个报告期占比最高值** |
| periods | 参与统计的报告期数 |
| board / industry | 板块 / 行业 |
| **risk_flag** | **占比 ≥ 30% 标记为 1** |
| report_date / notice_date | 报告期 / 公告日 |

**为什么重要：** 商誉是并购溢价的沉淀，**减值不经过现金流、直接砸利润**。占比越高，一次性洗掉净资产的概率越大。实测 Top5：

| 代码 | 名称 | 商誉占净资产比 | 商誉 | 净资产 |
|---|---|---|---|---|
| 002775.SZ | 文科股份 | **1152.2%** | 4,406 万 | **382 万** |
| 002313.SZ | 日海智能 | 244.1% | 2.16 亿 | 0.88 亿 |
| 002524.SZ | 光正眼科 | 205.2% | 2.41 亿 | 1.18 亿 |
| 002640.SZ | 跨境通 | 154.9% | 10.6 亿 | 6.86 亿 |
| 002647.SZ | 仁东控股 | 131.6% | 9.04 亿 | 6.87 亿 |

占比 > 100% 意味着**净资产已被商誉全部占满甚至为负**，属于典型减值雷区。全市场 **110 只**占比 ≥ 30%。

**报告期覆盖：** 实测东财仅提供 **4 个报告期**（2024-12-31 / 2025-12-31 / 2026-06-30 / 2026-09-30），
更早的分区（2025-09-30、2026-03-31 等）接口返回空 —— 这是**上游口径限制**，不是脚本问题。

## 四、踩坑 10：polars 批内 schema 推断（**新增，重要**）

### 现象

写入商誉 3,001 行，第 1 批 400 行成功，第 2 批直接 **500 Internal Server Error**：

```
polars.exceptions.ComputeError: could not append value: -0.413195 of type: f64
to the builder; make sure that all rows have the same schema
or consider increasing `infer_schema_length`
```

### 根因

服务端写入路径是 `rows_to_parquet()`（`ext_data.py:995`）：

```python
df = pl.DataFrame(rows)      # 一次性建表
```

polars 推断列类型时**只看批内前若干行**（默认 100）。构造最小复现：

```python
rows = [{"symbol": f"S{i}", "v": None} for i in range(150)]
rows += [{"symbol": "S999", "v": -0.413195}]
pl.DataFrame(rows)   # → ComputeError
```

前 150 行该列全为 None → 推断为 Null，第 151 行冒出浮点 → 崩。

**这和坑 2（int/float 混批）是同一个家族，但触发条件更隐蔽：**
不需要类型不同，只要**列在批内前缀是全空、后面才有值**就会炸。
本次触发列是 `se_chg_pct` / `goodwill_ratio_qoq` 这类**大部分股票为空的字段**。

### 解法

不要按固定长度切片，改成**按「非空字段指纹」分组**，指纹相同的行才进同一批：

```python
groups = {}
for r in rows:
    sig = tuple(sorted(k for k, v in r.items() if v is not None))
    groups.setdefault(sig, []).append(r)
for sig, grows in groups.items():
    for i in range(0, len(grows), 400):
        post(table, grows[i:i+400])
```

同一个指纹的批内，每列的「非空前缀长度」一致，polars 不会再推断出 Null 列。
`fetch_batch2.py` 的 `ingest()` 已内置该逻辑，**后续接新表建议统一复用它**。

## 五、踩坑 11：`Push2RateLimitError` 其实是本机代理断连（**新增，最坑**）

### 现象

拉个股资金流时，akshare 反复抛：

```
Push2RateLimitError: 东方财富 push2 行情服务器断开了连接，通常是短时间内请求过多，
当前 IP 被临时限流。首次限流一般约 5 分钟后恢复，反复触发后可能需要 40 分钟以上；
等待期间不要重复调用东方财富的行情接口，否则会延长限流。
```

**按字面理解会走进死胡同** —— 等几十分钟再试，依然失败。

### 排查过程

```python
# 同样的 URL，一次成功一次失败，说明不是"IP 被限流"
requests.get(push2_clist, params={...,"fields":"f12,f14,f62"})      # → 200 ✅
requests.get(push2_clist, params={...,"fields": 更多字段})           # → ProxyError ❌
```

失败栈里真正的信息在最底层：

```
urllib3.exceptions.ProxyError: ('Unable to connect to proxy',
    RemoteDisconnected('Remote end closed connection without response'))
```

### 根因

本机环境变量设置了代理：

```
HTTP_PROXY  = http://127.0.0.1:7897
HTTPS_PROXY = http://127.0.0.1:7897
```

`requests`（akshare 底层）默认走系统代理。该代理**在处理 push2.eastmoney.com 时会直接断开连接**，
akshare 把这个 `RemoteDisconnected` 捕获后包装成了语义完全错误的 `Push2RateLimitError`。
所以这不是限流，**等多久都没用**。

### 解法

会话级绕过代理：

```python
s = requests.Session()
s.trust_env = False        # 关键：忽略 HTTP(S)_PROXY
s.headers.update({"User-Agent": "Mozilla/5.0",
                  "Referer": "https://data.eastmoney.com/"})
```

`fetch_batch2.py` 的 `_direct_session()` 已封装该逻辑，并直接用 push2 的
`api/qt/clist/get` 拉取，**不再经过 akshare 封装**（顺带摆脱了它对接口字段改名的依赖）。

### 收益

| | akshare 封装 | 直连 push2 |
|---|---|---|
| 成功率 | 反复失败 | 稳定 |
| 行数 | 5,302（**被截断**） | **5,927**（全市场） |
| 耗时 | — | 60 页约 25 秒 |

**一致性校验：** 主力净额 == 超大单 + 大单，5,572 行全部相符，**0 行异常**。
