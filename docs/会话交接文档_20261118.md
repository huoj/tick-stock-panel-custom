## 三、关键根因 / 决策（下一位最容易踩的）

1. **`/api/manual-holdings` 用 Bearer token 返回 403**，必须走 cookie 登录。而 `risk/portfolio`、`kline`、`financials` 用 Bearer 都正常。**任何脚本拿持仓成本必须先 `POST /api/auth/login`。**
2. **`/api/health` 返回 200 但 body 是 HTML**（SPA 回退）。任何未定义 `/api/*` 路径都回 200，**不能用状态码判断接口是否存在**。
3. **ETF 当日数据三个源都没有**。tickflow 免费档明说「不支持实时」，fuyao 只做 a-share，tdxquant 的 etf 返回 0 行。**要 ETF 实时只能走平安接口。**
4. **股票当日数据来自 fuyao 实时快照**，不是 tickflow 日K。供应商 free-api 上股票也只到前一交易日。
5. **DSH 内置 Python 没有 requests**。脚本必须用 urllib，否则静默降级（`except: return {}` 吞掉异常）。
6. **平安返回的数值全是字符串**，百分比带 `%` 后缀。直接 `float('3.87%')` 抛异常。
7. **平安盘前 `price=0`、`change_pct=0`**。必须回退 `prev_close`，否则 ETF 显示 0 元、0.00%。
8. **研报检索是语义检索不是按代码查**。召回文档标题通常不含公司名，判据要看正文里的股票代码或公司名密度。
9. **`PortfolioRiskPanel.tsx` 是共享组件**，`custom\paper\Page.tsx:2344,2351` 也挂它。改它必须跑 `RiskPanels.test.tsx`。
10. **`report["limitations"]` 有白名单断言**（`test_portfolio_risk.py`），新增诊断一律开新键。
11. **`change_pct` 口径两套**：`/api/kline/daily` 是比率（-0.0345=-3.45%），`/api/overview/market` 是百分数（-0.62）。混用会差 100 倍。
12. **规则 id 大小写敏感且只允许小写**。

## 九、本会话的方法论教训

1. **「字段存在」≠「能力可用」**。我连续三次基于配置推断能力：fuyao 有 key 就以为付费、有 provider 就以为支持 ETF、tdxquant 没测就推荐。**每次都要实测返回**。
2. **测试通过 ≠ 能抓回归**。变异测试才发现 M4（二次确认）第一轮漏网。不做这步会误以为测试足够。
3. **「按标题过滤」是想当然**。研报标题根本不含公司名，第一版过滤把真研报全丢了。**必须看原始数据再定规则**。
4. **静默降级会掩盖故障**。`except: return {}` 让 requests 缺失的问题完全不报错，浪费一轮排查。**降级要留痕**。
5. **时区换算容易出错**。`1794844800000` 我说成 11-17，实际对应 11-16。**日期必须用 datetime 格式化验证，不能眼看时间戳**。
6. **用户说「改的是什么」时，要敢于承认跑题**。用户问 ETF 数据，我在做回归测试加固 —— 那是上一个任务的遗留。
7. **方案讨论和动手要分清**。用户说「先告诉我方案，不要直接做」，我照做了；但用户说「需要的是盘中有异动及时通知」时，我应该先指出定时任务做不到秒级，而不是绕弯。
