# 个股分析标准框架

> 起因：2026-11-13 的用户反馈「这次分析挺好的，以后股票分析按照这种方式分析」。
> 本文把那次分析的骨架固化下来，成为每次个股分析的固定套路。
>
> 配套脚本：`backend/scripts/analyze_stock.py`（一条命令产出全部原始数据）。

## 一、这套框架解决什么问题

普通股票分析的通病是：**结论先行、指标堆砌、没有概率、没有赔率**。
「MACD 金叉了所以会涨」——这不是分析，这是许愿。

本框架只做三件事，按此顺序：

1. **今天发生了什么**（K 线性质，不是涨跌多少）
2. **现在在什么位置**（结构 + 筹码 + 关键位）
3. **接下来各情景的概率与赔率**（用历史同形态样本说话）

最后才是判断和操作建议。**没有前三步的数据支撑，不许给结论。**

## 二、五个固定步骤

### 步骤 1：K 线性质（不是涨跌幅）

只看涨了 1.5% 没有意义。要拆出**这根线是谁买的**：

| 度量 | 怎么算 | 说明什么 |
|---|---|---|
| 实体占比 | `|收-开| / (高-低)` | 越高越是单边控盘；低于 30% 是犹豫 |
| 收盘分位 | `(收-低) / (高-低)` | >80% 买盘承接到底；<20% 冲高回落 |
| 上影/下影 | `高-收` / `开-低` | 长上影是抛压；长下影是承接 |
| **量比（今/20日均量）** | `量 / mean(量,20)` | **这是最关键的一列** |

量能与形态的组合判读（必须背下来）：

| 组合 | 含义 | 后续可靠性 |
|---|---|---|
| 缩量（<70%）+ 光头阳 + 收盘高位 | **抛压枯竭** | 下跌末端出现 → 高；高位出现 → 低 |
| 放量（>150%）+ 光头阳 | **资金推动** | 需次日接力，否则回落 |
| 放量 + 长上影 | **出货** | 危险 |
| 缩量 + 长下影 | **试盘 / 承接** | 中性偏多 |
| 放量下跌 | **恐慌 / 加速** | 看位置：低位是底，高位是顶 |

**判读口诀**：缩量阳线看"卖的人走了"，放量阳线看"买的人来了"。
前者只要没人卖就能涨，后者需要持续买。**位置决定哪种更靠谱。**

### 步骤 2：趋势结构（三条线定性质）

```
现价 vs MA20 / MA60 / MA120
```

| 形态 | 判定 |
|---|---|
| 价 > MA60 > MA120，且 MA60 上翘 | **中期上升趋势**，回踩是买点 |
| 价在 MA60 上方，MA5/MA10 在价上方 | **上升趋势中的调整**（最健康） |
| 价 < MA60 < MA120 | **中期下降趋势**，反弹是卖点 |
| MA60 与 MA120 纠缠 | **震荡市**，高抛低吸 |

**必须同时报出「距前高/前低多少」**，否则读者不知道自己在山腰还是山脚。

### 步骤 3：指标（只选四个，不堆砌）

| 指标 | 只回答一个问题 |
|---|---|
| **RSI14** | 有没有超买/超卖，还有多少空间 |
| **MACD（DIF/DEA/柱）** | 动能方向，以及**柱线是在扩张还是收敛** |
| **布林带（上/中/下）** | 极值位置；**下轨/上轨和实际低点/高点是否重合**（重合=有效） |
| **ATR14** | 日均波动是多少元、多少 % —— 用来定止损距离 |

**不要列超过这四个**。KDJ、CCI、OBV 之类对普通投资者没有增量信息，
反而稀释重点。

指标必须给出「读数 + 一句人话解读」，光给数字等于没分析。

### 步骤 4：筹码分布 + 关键位（这是最有用的一步）

#### 筹码分布算法

```
把近 60 日按价格分成 12 档
每档累加落在该档的成交量
算出每档占总量的百分比
```

**为什么这个比画线有用**：它直接告诉你钱堆在哪。

- **上方最密集的那一档 = 最强阻力**（套牢盘要解套就会卖）
- **下方最密集的那一档 = 最强支撑**（成本区的人不愿割）

#### 关键位必须成表

| 类型 | 价位 | 距现价 | 依据（必须写清，不能只写数字） |
|---|---|---|---|
| 强阻力 | … | +x% | MA20 + 套牢区 + 前高 + 缺口 |
| **现价** | … | — | — |
| 强支撑 | … | -x% | MA60 + 布林下轨 + 前低 |

再加**摆动高低点**（5 日窗口的局部极值）和**未回补缺口**。

### 步骤 5：历史同形态统计（本框架的核心价值）

这一步是普通分析和专业分析的分水岭。

```python
# 找出历史上形态相同的日子
条件 = 前一日下跌 AND 当日上涨 AND 成交量 < 20日均量 * 0.7
# 统计它们之后 1/3/5/10 日的涨跌
```

**必须同时给出无条件基准**，否则读者无法判断这个胜率有没有意义：

| 前瞻期 | 形态样本胜率 | **无条件胜率** | 结论 |
|---|---|---|---|
| 次日 | 61% | 47% | 有信息量 |
| 3 日 | **72%** | 49% | 有信息量 |

**没有基准的胜率是骗人的**。A 股无条件上涨概率本来就有 47~50%，
如果形态样本是 52%，那就是噪声，必须明说。

#### 样本量必须披露

18 个样本的 72% 胜率，置信区间可能覆盖 50~88%。**必须写出来**，
不能拿 72% 当确定概率用。

## 三、输出分层：同一份数据，两种说法

用户明确要求「让普通投资者更容易看得懂」。因此每个结论都要有**两套表达**：

### 专业版（保留了精度的说法）

> RSI14 为 49.4，从 45.0 回升，处于中性区间；MACD 柱 -0.69 空头动能仍在
> 但收敛；布林下轨 97.39 与昨日低点 97.79 重合，验证支撑有效。

### 大白话版（同一件事，换成钱和日子）

> 现在不贵也不便宜，属于「刚跌完、还没转强」的状态。
> 昨天跌到 97.79 就有人接了，因为那个位置正好是近两个月的平均成本区，
> 大家不愿意在那个价割肉。

### 换算规则（大白话版必须做的四件事）

1. **钱**：`10 万元买入 = 多少股 × 现价`，然后每个情景换成「赚/亏多少钱」
2. **日**：把「ATR 2.44 元」换成「10 万仓位每天正常涨跌 2200 元」
3. **时间**：把「20 日年化波动 30.4%」换成「一年正常波动 ±3 万」
4. **对比锚**：把收益率换成「相当于银行利息的几倍」或「分红够吃几顿饭」

### 情景表的写法（大白话版核心）

不要写「目标位 101.49」，要写：

| 情景 | 目标价 | 10 万块变成 | 概率 |
|---|---|---|---|
| 跌到 96.56 | 96.56 | **亏 3258 元** | 25% |
| 到 101.49 | 101.49 | **赚 1179 元** | 30% |

**读者一眼能看出「亏的时候亏多少、赚的时候赚多少」** —— 这才是决策需要的信息。

## 四、必须说清的三类不确定性

每次分析末尾固定写这三条，缺一不可：

1. **样本量够不够**：历史同形态只有 N 例，统计置信度有限
2. **数据来源限制**：指标是现算的（enriched 分区无指标列）、
   与商业软件可能有小数差
3. **你看不见的变量**：基本面、机构调仓、政策、未公告事项 ——
   **技术面只能说"钱在怎么走"，说不了"为什么"**

## 五、禁止事项

- ❌ 不给「必涨/必跌」的确定判断
- ❌ 不给没有概率标注的目标价
- ❌ 不列超过四个技术指标
- ❌ 不省略「无条件基准」的对比
- ❌ 不省略止损位（任何操作建议必须带证伪条件）
- ❌ 不用「主力洗盘」「资金吸筹」这类无法验证的叙事

## 六、脚本用法

```bash
cd backend
.venv\Scripts\python.exe scripts/analyze_stock.py 600941.SH
.venv\Scripts\python.exe scripts/analyze_stock.py 600941.SH --capital 500000
```

输出：K 线性质、趋势结构、四指标、筹码分布、关键位、历史同形态统计、
10 万/自定义资金的盈亏换算。

**脚本只出数据，不出结论。** 结论由分析者基于数据给出 —— 这是刻意的：
数据可以自动化，判断不能。
