## 二、本会话完成的六条主线

### 主线 A：平安 provider 插件（能力路由新增 `etf`）

**做了什么**：新增 `backend/app/plugins/pingan/`，把平安证券接成 TSP 的数据源。

**关键决策（都是实测后否掉的原方案）**：

1. **不接 `daily`**。平安 `klineData` 返回**前复权**价且无参数可切换
   （`adjust=none/0/nofq` 全被忽略）。与东财 `fqt=0`（不复权）逐日对比：
   600941 近 180 日 **149 天背离（最大 -4.71）**、000651 **126 天（-5.20）**、
   510300 除息后当日即背离。内部契约要求日K入库为 raw 价，前复权进库会
   静默算错复权因子与全部下游指标 → **日K一列都不取**。
2. **新开 `etf` 独立能力，不复用 `realtime`**。声明 realtime 意味着 5583 只股票
   全市场轮询全路由给它，只提供 ETF 的源会让股票整轮空转。ETF 只做
   「补本轮未覆盖标的」。
3. **快照的当日 OHLC 是原始价**（前复权锚点为「最新」，当日价恒等于 raw），
   实测今日 bar 与 quote 逐字段一致 → 可安全作为当日值。

**改动清单（5 处必须一起改，漏一处就是静默不可用）**：
`CAPABILITY_REGISTRY` → `preferences` getter → `_current_routing()` →
`api/settings.py` 的**入参模型和 3 处返回体** → 前端 `ProviderField` +
`DEFAULT_ROUTING` + `effProvider`。

> 本会话就漏过 `DataProvidersIn` 与 `get_preferences`，靠端到端实测才发现。

### 主线 B：ETF 估值分位（补「数据缺口清单」的缺口 1）

**接口实测（决定实现方式的四件事）**：

1. 信封**没有 `data` 层**：`{responseCode, currentDate, total, rows}`。
2. 数值全是字符串但**单位混杂**：分位/涨跌/ROE/费率是小数，`yielD`/
   `foldingPremiunRates`/`scopeIncreaseM` 已是百分数，`scope`/`turnVolume20`
   反而是数字。写成「一律 ×100」或「一律原样」都会错一半。
3. **`scope` 与 `turnVolume20` 源端完全不可筛选**（任何操作符 total=0）；
   `type:8`（数组集合）被**静默忽略**。
4. **没有页码参数**，`pageSize` 上限 100 → 只能靠 `code` 游标翻页：
   `wheres=[{code, type:3, 上一页末个}]` + `orderBy=code` + `orderType=A`。
   实测 **18 页覆盖 1721 只**（末页 38 条短页结束）。

**最重要的发现：源端筛选与排序按字符串语义，不可信**：

| 检查 | 源端 wheres | 本地数值口径 |
|---|---|---|
| `orderBy=pe` 首条 | 10.0823 | **6.482** |
| `pe < 20` | 676 | **717** |
| `pe<20 且 规模宽基` | 201 | **180**（源端竟更多） |

分位那几组看起来对得上（742/874/141/517/785）**纯属巧合** —— 都是 `0.x`
位数相同，字符串序恰好等于数值序。**换一批数据就错，且不报错。**

→ 最终实现：源端只负责「按 code 游标翻页取全市场」，筛选与排序**全部在本地**
对归一后的浮点列做。副产品：`scope_min` / `amount_20d_min` 也能筛了
（源端这两个字段任何操作符都返回 0 条）。

**产物**：`ext_etf_valuation`（1721 行 × 29 列，每日 17:20）+
`GET /api/etf-valuation/screen`（15 个筛选参数 + `scope_min`/`amount_20d_min`）+
`PullConfig.adapter` 框架能力。

**验证**：落库 parquet 独立复算交叉校验，**9 组筛选 + 2 组 TopN 全部逐条一致**。

### 主线 C：热股榜单（TSP 原本完全没有的关注度维度）

**四张表，一榜一张**：`ext_hot_stock`（热搜）/ `ext_hot_select`（加自选）/
`ext_hot_watch`（浏览）/ `ext_hot_surge`（飙升）。

**为什么必须拆表**：`write_ext_parquet` 去重键是 `[symbol]`，同一票在四榜各出现
一次，塞一张表会被去重成一行。

**接口实测（第三套信封）**：
- `{status, errmsg, results}`，**成功值是 `status == 1`**（行情是 `code==0`、
  金库是 `responseCode=="0"`）。
- `time_range` 必须是**整数**（1=1h，2=24h），传 `"1d"` 直接 400。
- **非法取值不报错**：`time_range=3` → `{status:1, total:0, list:[]}`。
  空榜单与参数错误在协议上不可区分 → 强制前置校验。
- `total` 恒 100（榜单深度上限），`size=101` 只回 100 条。

**产物**：四张表（各 200 行 = aStock+etf 各 100）+ `GET /api/hot-stock/list` +
`GET /api/hot-stock/boards`。

### 主线 D：研报正文（把评级计数升级成「券商说了什么」）

**接口实测（第四套信封）**：
- `{records, msg}`，HTTP 200 即成功。
- **必须带平台内置 Bearer token**，不加直接 **HTTP 500**（不是 401）。
- **`score_threshhold` 是服务端字段名（双 h），但服务端完全不按它过滤** ——
  同一 query 传 0.05 与 0.6 返回**完全相同的 44 条**。阈值只能在本地做。
- 一条 record 只有 `content/metadata{path,description}/score/title`。
- 同一研报被切成多个片段分别返回（同 `metadata.path` 的 `id=`）。

**一个必须说的取舍：删掉了首版的 4 列**。首版我写了
`institution`/`rating`/`note_date`/`date_source`，实测 27 篇去重文档后：

| 想抽的 | 实测可得率 |
|---|---|
| 机构名 | **1/27，且那 1 条是错的**（从「基金代销与证券业务」抽出「基金代销与证券」） |
| 评级 | **0/27** |
| 可信发布日期 | **1/27**（其余是引用文献日期或「截至2026年7月31日尚未回购」的数据时点） |

根因：**片段是骨架**，27 篇里 30% 不到 200 字，只有「标题 + 核心观点 + 代码」。
→ 结论：**与其给假数据，不如只给片段原文**。10 列，不含这三个字段。
回归测试 `test_row_has_no_heuristic_metadata_columns` 专门守这条线。

**检索形态实测**：**用 6 位代码召回最好**（代码 15/19/14 篇全命中；名称只召回
6/12/14 篇）。标签预筛选（`label_value_ids`）**不能当 symbol 过滤器** ——
`半导体 + label 125(行业周报)` 首条返回「新材料行业周报」。

**产物**：`ext_research_note`（8 行 × 10 列，每日 17:30）+ `GET /api/research-notes/search` +
`GET /api/research-notes/tracked`。

### 主线 E：盘中化 + 开箱预置

**热股盘中化（1、2 项）**：

```jsonc
// 之前: 每日 17:10 一次
"schedule_time": "17:10", "schedule_period": "daily"
// 现在: 每 30 分钟, 只在交易时段
"schedule_minutes": 30,
"time_window_start": "09:30", "time_window_end": "15:00",
"time_field": "__pull_ts__"        // 保留名: 写入时注入拉取时刻
```

关键在 `time_field`。不配时间列时同一票当天多次拉取被**覆盖成最后一行**，
只剩「当前热度」；配了之后每盘各存一行，才算得出「热度涨了多少」——
**而增量才是这个维度唯一有价值的信号**。

**顺带修的两个真实缺陷**：
1. **区间制没有交易日过滤**。`schedule_trading_only` 原先只在固定时刻模式生效，
   区间制**周六日照拉**（一天白烧 16 次额度）。抽出 `_interval_skip_reason()`。
2. **`_in_time_window` 内部硬编码 `cn_now()`** → 门禁逻辑不可测。加可选 `now` 参数。

**迁移保守**：`_needs_intraday_upgrade()` 只认出厂形状（`17:10` + `1440` 分钟 +
无自定义时间列）三者齐全才升级；用户改过任一项的**整份不动**（只改一半会得到
既非每日也非盘中的混合配方）。

**开箱预置（3、4 项）**：`backend/app/services/pingan_presets.py`

1. **价格分位因子** `uf_price_percentile_250d`：
   `(ts_rank(close, 250) - 1) * 100 / 249` → 0=近一年最低，100=最高。
   与平安的**估值分位**互补：两个都低 = 真便宜；价格低但估值高 = 盈利在崩。
   口径已手工核对：159682.SZ 现价在近 250 日排第 2 → `(2-1)*100/249 = 0.40`，一致。
2. **四条信号**：`pa_etf_deep_value`（分位≤20 且折价）、`pa_etf_overheated`
   （分位≥85 且近一年>30%）、`pa_hot_rising`（热搜前 20）、
   `pa_research_new_coverage`（研报≥2 篇）。
3. **四条规则**：signal 型，`op="truth"` 引用上面的信号列，绑播种时的持仓∪自选快照。

**刻意没播种的两条**：
- **「热度跃升」规则**：`hot_value` 跨期增量的方向还没回测验证过（顺势还是反向
  未知），现在写任何阈值都是猜的。需先落 2–4 周数据。
- **个股估值分位信号**：`ext_valuation` 只有 11 个分区，算不出 3 年分位。

### 主线 F：额度事故复盘（**本会话最重要的教训**）

**用户发现今天平安接口用了 1675 次。查账结果**：

| 用途 | 次数 | 占比 |
|---|---|---|
| **ETF 快照补拉** | **1377** | **82%** |
| ETF 估值分位（18 页 × 1 轮） | 18 | 1% |
| 研报检索（2 轮 × 10 标的） | 20 | 1% |
| 热股榜单（含额度用尽后失败） | 24 | 1% |
| 限流退避重试 | 2 | — |
| 我的调试脚本（直连平安，不走 TSP 日志） | 234 | 14% |

**根因**：`_supplement_etf_quotes` 我实现了「只补本轮未覆盖的 ETF」，
**但忘了节流**：

```
行情轮询 4s 一轮  ×  4 小时  ×  3 只 ETF  =  上千次/日
```

而 ETF 当日价格在 **4 秒内根本不变**。不是数据需要，是设计缺陷 ——
我自己在文档里写了「额度 2000/日」却让补拉每 4 秒跑一次。

**后果链**：14:49 打到 429 → 之后 100 次失败重试全部空转 → 热股与研报被连坐
（`DAILY_QUOTA_EXCEEDED`）→ 盘中的热股增量一条没落下来。

**修法**：

```python
ETF_SUPPLEMENT_TTL_S = 60.0       # TTL 内复用上次结果, 不打接口
ETF_SUPPLEMENT_BACKOFF_S = 600.0  # 失败/429 后 10 分钟不再尝试
```

整日 1377 → 约 **240 次**（降 83%）。失败时**保留旧缓存**，不因一次限流清空行情。

**验证**：新增 `test_quote_etf_supplement_throttle.py` **8 条**；
**变异测试**：把 TTL 改回 0 → 3 条立刻失败（证明测试真能抓）。

## 三、关键根因 / 决策（下一位最容易踩的）

1. **`/api/health` 返回 200 但 body 是 HTML**（SPA 回退）。任何未定义 `/api/*`
   路径都回 200，**不能用状态码判断接口是否存在**。
2. **`/api/kline/daily` 的 `days` 最小 10**（传 2 会 422）。
3. **状态接口是 `/api/intraday/status`，刷新是 `POST /api/intraday/refresh`**
   （`/api/quotes/*` 不存在，是 SPA 兜底）。
4. **`/api/manual-holdings` 用 Bearer 返回 403**，必须走 cookie 登录。
5. **新增能力必须 5 处一起改**（见主线 A），漏任何一处都是「静默不可用」。
6. **`PullConfig` 有 `__slots__`**：加字段必须**四处同改**（`__slots__` /
   `__init__` / `to_dict` / `from_dict`），另外 `ext_data_schema.PullConfigReq`
   与 `api/ext_data.configure_pull` 要各加一处，否则 UI 保存配置时会把字段抹掉。
7. **`signal_*` 与 `monitor_rules` 的字段白名单不是同一个**：
   - 信号定义用**动态**的 `custom_signals.allowed_fields()`（含扩展列、注册表因子）
   - 监控规则的阈值条件用**静态**的 `ALLOWED_FIELDS`
   → 规则里直接写 `ext_*` 会被拒。正确路径：**先建信号，再用 `op="truth"`
   引用信号列**（`signal_`/`csg_` 前缀）。
8. **预置播种必须排在 `load_runtime_registry()` 之后**（等基础信号与因子先入表），
   所以写因子文件后必须**立即 `register_definition()`** —— 只写文件的话当次启动
   注册表里没有它，引用该因子的信号会报缺列，要等下次重启才自愈。
9. **`scope="watchlist_group"` 要求 `group_id` 非空**（`validate` 强制）。
   播种时不知道用户想要哪个分组 → 用 `symbols`，播完可改。
10. **`attach_ext_columns` 在 `df` 没有 `date` 列时直接 `continue`**
    （timeseries 无法 PIT 对齐）。ETF/指数单行帧、以及测试夹具无 date 时，
    扩展列全部跳过 → 会看到 `missing dependencies` 告警。
    **这是设计行为，不是配置错误**。实测：有 date 时注入正常
    （002242 取到 rank=1、hot_value=66249，与榜单一致）。
11. **`collapse_ext_rows_at` 是收敛工具**：`at=None` 取末盘，`at="10:00"` 取该
    时刻或之前最近一盘（PIT 安全）。字段引用可写 `ext_hot_stock.hot_value@10:00`。
    **信号/因子路径自动收敛**（`_timeseries_frame` 对 `(symbol,date)` keep="last"），
    多盘不会 join 扇出。
12. **改 .py 一律用 edit 工具或 write 全量重写，禁止 pwsh `Set-Content`**。
    本会话用 `(Get-Content f) -replace ... | Set-Content f -NoNewline` 把一个
    473 行的文件压成 1 行，靠重写整个文件恢复。
13. **并发跑 pytest 会互相污染临时目录**。本会话两次「失败数异常」（51 vs 27）
    都是因为同时有另一个 pytest 进程在跑。

## 九、本会话的方法论教训

1. **额度要当成本来设计，不是「反正还有」。**
   ETF 补拉 4s 一次这个缺陷，我在写的时候就该发现：文档里明写 2000/日，
   而 4s 轮询 × 4 小时 = 3600 轮。**「频率 × 时长」要先算一遍再写代码**。

2. **失败重试要有退避。** 今天 100 次失败重试全部空转，因为额度用尽后
   每 4 秒重试一次。退避不是优化，是**不把日志和额度一起烧掉**的必需品。

3. **供应商接口的「筛选」不可信，先验证再依赖。**
   平安按字符串序排序/筛选这件事，如果我不做交叉校验，`pe<20` 会静默少返
   41 只、而且没人会发现。**任何跨数据源的口径差异都要用独立复算验证。**

4. **源端不给的字段不要「抽」。**
   研报的机构/评级/日期，我第一版抽了，实测 1/27、0/27、1/27 且那 1 条是错的。
   **正则能匹配 ≠ 数据可信。** 宁可留空并说明，也不要给假数据。

5. **「字段存在」≠「能力可用」。**
   `ext_*` 字段确实进了白名单，但盘中路径没有 date 列时全部跳过；
   配置里有 `time_field` 但当天落库是升级前的。**都要实测到底层文件。**

6. **并发跑测试会骗你。** 两次看到「失败数异常」（51 vs 27），都是因为
   同时有另一个 pytest 在跑。**基线对比必须串行。**

7. **改文件用 edit/write，不要用 shell 重定向。**
   `Set-Content -NoNewline` 把一个 473 行文件压成 1 行，白花一轮时间恢复。
