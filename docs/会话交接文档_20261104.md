## 六、踩坑记录（**11 个，务必阅读**）

### 坑 1：ingest 要求每行包含全部声明字段

```
400 第 1 行缺少字段: announce_date, avg_mv, ...
```

**解法：** 每行先填充 `{k: None for k in 全部字段}`。

### 坑 2：dtype 不一致导致"覆盖写入"

**现象：** 写 5,578 行，查询只剩 378 行。

**根因：** 整数批次推成 `Int64`、含缺失的批次推成 `Float64`，concat 报
`type Int64 is incompatible with expected type Float64`，服务端**降级覆盖写入**。

**解法：所有数值字段强制 `float`。**

### 坑 3：symbol 为 None 导致折叠成 1 行

**根因：** snapshot 模式按 `symbol` 去重，字段白名单漏了 `symbol` → 全是 None → 折叠成 1 行。

**解法：** `symbol` 单独处理，不依赖白名单判断。

### 坑 4：沪深两融混合批次导致 500

**根因：** 深市有 `total_balance`/`short_balance`，沪市为 None，同批内 polars 推断出两种 schema。

**解法：沪深分开批次写入。**

### 坑 5：两融数据是 T+1 发布

```
20261104 深市: 0 行     ← 当天没有
20261103 深市: 2118 行  ← 昨天有
```

**解法：** 自动回溯最多 7 天。

### 坑 6：timeseries 表的 `/rows` 只返回最新分区

```
/rows?limit=1                    → 只有最新一天
/rows?date=2024-11-14            → 指定分区
/series?symbol=xxx&start=&end=   → 完整时序
```

**ext_gdhs_ts 实际 249 万行（477 分区），`/rows` 只显示 5,338 行。**
**不影响因子回测**（引擎直读全部分区）。

### 坑 7：季度可用日多非交易日 → 因子覆盖率仅 1.22%

**解法：** 前向填充到每个交易日（PIT 正确）。

**结果：覆盖率 1.22% → 91.0%**

### 坑 8：Windows 无符号链接权限

```
OSError: [WinError 1314] 客户端没有所需的特权
```

**影响：** 1 个上游测试失败，**非代码问题**。

### 坑 9：上游 evidence 并发写 Bug

```
FAILED test_concurrent_manifest_writes_never_replace_an_existing_version
ValueError: 回测记录目录无效
```

**已用对照实验证明：纯净上游版本同样失败。** 触发条件是「同一 run_id 并发写」，
**日常回测不受影响**。**决定不修**，避免增加升级冲突面。

### 坑 10：polars 批内 schema 推断（第二批新增）

**同坑 2/4 的根因总结**，参见 `docs/第二批数据接入说明.md` 第四节。

### 坑 11：`Push2RateLimitError` 其实是本机代理断连（**最坑**）

**现象：** 东财接口报「IP 被临时限流」。

**实测：** 同样的 URL 一次成功一次失败 → **不是 IP 限流**。

**根因：** 本机代理连接问题。

**解法与收益：** 参见 `docs/第二批数据接入说明.md` 第五节。
