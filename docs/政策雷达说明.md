# 政策雷达（MVP）—— 事件 → 自选股 → 告警

> 完成时间：2026-11-04
> 脚本：`D:\deepseek_path\databridge\policy_radar.py`（主逻辑）+ `policy-radar.ps1`（包装器）
> 定时任务：`TSP-Policy-Radar`（每日 18:30）
> 输出：`tick-stock-panel\data\user_data\alerts.jsonl`（`source = policy_radar`）

---

## 一、它解决什么问题

系统此前**只有价格，没有事件**：`stock_analyzer.py:167` 的"消息面"是标注
"[推断]"的价量猜测，`market_recap.py` 的新闻检索是未接入的 TODO。
所以系统永远不知道"发生了什么"，只知道"价格动了"。

本模块补上 **事件→影响** 这一层，且**只针对自选股**。

## 二、数据链路

```
① 采集
   个股公告   stock_notice_report(date=今天) → 本地过滤到自选股
              （踩坑：stock_individual_notice_report 实际返回全市场，必须本地过滤）
   国内政策   stock_info_global_ths / _em / _cls  按政策关键词过滤
   国际政治   stock_info_global_futu / _sina / _cls 按地缘关键词过滤
   新闻联播   news_cctv(date)  ← 唯一可按日期回补的政策源（当天19点后才有，回退前一天）
        ↓
② 结构化（本地 AI，OpenAI 兼容，127.0.0.1:8326）
   {title, type, direction, strength, horizon, sectors, reason}
   提示词刻意**排除单一公司经营新闻**，只留宏观/行业/地缘
        ↓
③ 映射（混合：确定性 + 语义）
   预筛：事件 sectors ∩ 自选股(行业 ext_hy_ths + 概念 ext_gn_ths) → 缩小候选
   ETF：不在行业/概念表里，按名称关键词推断主题（"计算机ETF"→计算机/软件/算力）
   复核：AI 逐股判断"这条事件为什么影响这只股票"（给出具体传导路径）
        ↓
④ 落盘
   alerts.jsonl 追加，source=policy_radar，复用系统既有告警通道（SSE/飞书）
```

## 四、踩坑记录（**重要**）

### 坑 A：`stock_individual_notice_report` 返回的是全市场

```python
ak.stock_individual_notice_report(security="600941")  # 以为是个股
→ 实测 522 行，与 stock_notice_report 同样是全市场公告
```

**必须本地按代码过滤**，否则会把别人的公告算到自己头上。
现在改为：拉当日全市场公告 → 本地过滤到自选股（当天无公告的再回退个股接口）。

### 坑 B：财联社的标题经常为空，政策内容在"内容"字段

`stock_info_global_cls` 返回的"标题"大量为空字符串，正文在"内容"里。
若只读标题做关键词过滤，**政策条目会被全部丢掉**。
现在 `_norm()` 在标题为空时用内容前 60 字兜底。

### 坑 C：行政性公告会淹没有效信息

"业绩说明会""投资者关系活动记录表""股东大会资料"这类公告标题里含有
"业绩""股东"等关键词，会被粗粒度过滤放进来。
现在按 **公告类型白名单 + 标题黑名单** 双重过滤。

### 坑 D：AI 生成的标题不稳定 → 去重失效（**最隐蔽**）

同一条新闻，AI 每次给的标题都不同：

```
五部门：推进算力、通信基站和机房等基础设施节能降碳改造   ← event_src（原文，稳定）
  → 第 1 次跑："算力通信基础设施节能降碳改造"
  → 第 2 次跑："重点行业与算力设施节能降碳改造"
```

用 `event_title` 做去重 key 会导致**同一条新闻反复告警**。
**修正：key 必须基于 `event_src`（原文标题）+ 方向**：

```python
def key_of(sym, src, direction=""):
    return hashlib.md5(f"{sym}|{_norm_title(src)}|{direction}".encode()).hexdigest()[:16]
```

方向参与 key，是因为同一条新闻对不同板块方向可能相反（加息：利好银行/利空成长）。

### 坑 E：DSH 文件沙箱拒绝子进程写入数据湖目录

```
PermissionError: [Errno 13] Permission denied:
  D:\deepseek_path\tick-stock-panel\data\user_data\alerts.jsonl
```

即便 Windows ACL 允许、pwsh 原生 `Add-Content` 正常，
**从 python 子进程写入被拒**（从 python 里再起 pwsh 同样被拒）。

**解法：职责分离** —— `policy_radar.py` 只把告警 JSONL 打到 stdout
（`===ALERTS_JSONL_BEGIN===` / `===ALERTS_JSONL_END===` 包裹），
由**直接执行**的 `policy-radar.ps1` 负责追加到目标文件。

## 五、去重与幂等

- **权威来源是 `alerts.jsonl`**：每次运行都从中重建去重 key（而非只信状态文件），
  所以状态文件丢失/先于写入保存都能自愈。
- 状态文件：`databridge\data\policy_radar_seen.json`
- 限流：**每只股票每次最多 6 条**，防止单股公告刷屏。

**验证：** 连续运行时，第 2 次的新增降到个位数；同一新闻池内应接近 0。
（注意：免费快讯接口的历史深度极浅 —— 新浪 20 条≈5 分钟、财联社翻 20 页≈33 分钟，
所以**手动高频运行必然产生新条目**，这是数据源特性，不是去重失效。）

## 七、定位与限制（**必读**）

**它是雷达/排雷，不是交易信号。**

| 限制 | 说明 |
|---|---|
| **方向判断可能错** | "降准利好银行"不总成立，取决于市场是否已预期。AI 给的是**可能性排序**，不是事实 |
| **无法回测** | 免费新闻源历史只有几小时，没有历史事件库 → **无法验证"这个方法赚不赚钱"** |
| **无因果确认** | 事件影响是推理出来的，可能编造不存在的传导路径（已用"必须说出具体路径"约束，但不能根除） |
| **时效性** | 政策发布→行业受益→个股业绩链路长达数月，本模块只捕捉**短期情绪/预期**层面 |
| **不覆盖全部事件** | 只做自选股相关的国内政策/国际政治/公告，不是全市场事件库 |

**正当用途：** 降低漏掉重大事件的风险 + 给 AI 分析提供事实依据。
**不正当用途：** 当作买入/卖出依据。

## 九、P0 已落地：事件接入个股分析

### 改了什么

`backend/app/services/stock_analyzer.py`：

| 位置 | 改动 |
|---|---|
| 新增 `_load_events()` | 读 `alerts.jsonl` 中本标的的已识别事件（本地、快） |
| 新增 `_load_symbol_news()` | 读 `policy_radar_news.json`（**不从后端调 akshare**） |
| 新增 `_format_events()` | 把事件渲染成提示词片段 |
| `_SYSTEM_PROMPT` 第 5 节 | 从"**本期无新闻数据输入**、只能标注[推断]"改为"引用真实事件+新闻，并**客观指出事件与走势的矛盾**" |
| `_build_user_prompt()` | 注入事件/新闻；**无数据时明确标注**，避免模型编造 |

### 架构决定：后端不引入 akshare

后端 venv **没有也不需要** akshare（实测确认）。新闻由 `policy_radar.py` 采集，
随告警流一并发布到 `data/user_data/policy_radar_news.json`。
保持了"**外部采集归 databridge、后端只读本地**"的分工，也避免升级时的依赖冲突面。

新闻通过 `===NEWS_JSON_BEGIN/END===` 标记与告警同路输出，由 `policy-radar.ps1` 落盘
（同样为规避沙箱对子进程写入的限制，见坑 E）。

### 实测效果（宏柏新材 605366.SH）

**改动前**：消息面是"基于 K 线异动推断[推断]"——本质是猜。

**改动后**（原文摘录）：

> **已识别事件（方向为模型判定，非事实）**
> - **利空/中期**：「欧元区通胀超目标，12 月加息预期升温」…影响出口链、光伏、家电板块。
> - **利好/中期**：「9 月新增新能源发电项目 3552 个」…有机硅材料为光伏封装环节的上游之一。
> - **短期**：公司公告股东减持股份计划。
>
> **个股新闻**：10/11 披露「股东新余宝隆拟减持不超 1.93% 股份」；10/19「纳米硅项目研发仍处于中试阶段」…
>
> **需客观指出的两点矛盾**：其一，被模型判定为利好的新能源项目事件，与该股 10 月中旬以来
> 38.2% 的跌幅方向相反；其二，10/11 减持公告披露后，10/12 即出现跌停，
> 消息时点与价格急跌高度接近，而 10/19「纳米硅项目仍处中试阶段」的表述意味着
> 相关题材尚处早期研发阶段，尚未形成产业化落地。

**比"不再标注[推断]"更有价值的是：模型开始指出矛盾，而不是替消息面圆场。**
上例里它把"利好事件 vs 38% 跌幅"、"减持公告 vs 次日跌停"两处矛盾摆了出来，
这正是客观分析该有的样子。

ETF 场景（159586 计算机ETF）同样成立，且模型正确识别出：
**新闻全是指数上涨的事后报道**（"昨日收涨 6.24%"对应本 ETF 当日上涨），
并指出"消息面偏暖与价格中期下行方向不一致"。
