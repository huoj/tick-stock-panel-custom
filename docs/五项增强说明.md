## 一、财报与公告自动解析（把「去哪查」变成「查到了什么」）

### 新增模块

`backend/app/services/fundamentals_digest.py`

### 数据源与 PIT 口径

| 数据源 | 内容 | 时点过滤 |
|---|---|---|
| `financials_metrics` | 营收/净利同比、ROE、毛利率、负债率、EPS、BPS | **`announce_date`（公告日）** |
| `ext_forecast` | 业绩预告 | 无日期列 → 标为表内记录 |
| `ext_pledge` | 股权质押 | `trade_date` |
| `ext_dividend` | 分红送配 | 无独立日期列（`ex_date` 在字段内）|
| `ext_research` | 机构评级 | **无日期列 → 当前快照** |
| `ext_unlock` / `ext_insider` | 解禁 / 增减持 | 视列存在性 |

**PIT 红线**：财务数据用 `announce_date` 而不是 `period_end`。用报告期会让
2026Q3 的报表在 2026-07 就被「看到」，构成前视偏差（CONTRIBUTING §3.4）。

### 实测发现的三个真实约束（都已如实披露，不假装）

1. **`financials_metrics` 是快照存储 —— 每只票只有 1 行**
   （实测 5577 只标的 / 5577 行）。因此**做不了多期趋势**。
   代码里检测到 `len(revenue_trend) <= 1` 就追加限制说明。

2. **`ext_research` / `ext_forecast` 没有事件日期列** —— 前者是当前评级分布，
   后者只有报告期。它们不能冒充"近期事件"，代码里单列为 `snapshot_sources`
   并在 `limitations` 说明"只能代表现在、不能代表历史"。

3. **`ext_dividend` 的 `ex_date` 在字段里而不是独立日期列** —— 第一版把它当
   `date_col` 用，`filter` 找不到列会静默丢掉整块数据。已改为 `date_col=None`。

### 输出

- `metrics`: 最近一期 10 个指标（带单位）
- `revenue_trend` / `profit_trend`: 多期同比（有数据时）
- `announcements`: 业绩预告/质押/分红/评级，带日期与关键字段
- `unavailable` / `limitations`: 哪些没取到、为什么

### 接入行动卡

`build_checks(diagnosis, digest=...)` 现在：
- **有数据** → 直接把数字写成 check 项（`status="checked"`）；
- **无数据** → 明确 `status="unavailable"`，**不假装查过**。

行动卡新增 `fundamentals` 段，前端独立渲染。

## 二、强弱判定的历史有效性检验（最有价值的一项）

### 新增模块

`backend/app/services/strength_validation.py`

### 方法

滚动前推（walk-forward）：对历史每一天，用**当天及以前**的数据算一次判定
（复用 `stock_diagnostics.judge_strength` 同一套函数 —— 保证"回测里的判定"
与"卡片上的判定"是同一个东西），然后统计之后 5/10/20 日的真实收益，
与**同期全样本基准**对比。

### 五种判定

| verdict | 含义 | 行动 |
|---|---|---|
| `validated` | 各期方向一致、超额 ≥5pp | 可作筛选参考 |
| `weak_signal` | 方向一致、超额 2~5pp | 仅参考 |
| **`inverted`** | **一致地反着走** | **反向指标 —— 比无效更值得注意** |
| `no_edge` | 方向不一致，或幅度 <2pp | 无预测力 |
| `insufficient` | 样本 <30 | **不下结论**（不是"无效"）|

`inverted` 是单独一档，因为把它报成 `no_edge` 会掩盖一个更强的结论。

### 实测结果（76 只票，2754 个采样点，步长 10 天）

```
基准（任意一天之后）：5日 47.7% / 10日 48.8% / 20日 49.4%

偏强  n=340   41.8% / 41.2% / 40.3%   → -5.9pp / -7.6pp / -9.1pp  【inverted】
偏弱  n=1046  51.1% / 51.0% / 50.0%   → +3.4pp / +2.2pp / +0.6pp  【no_edge】
方向不明 n=1368 46.7% / 49.0% / 51.2% → 偏离 ≤1.8pp              【validated】
```

**结论：这套规则在样本上是反向的。** 被判为「偏强」的标的后续 20 日
跑输基准 9.1pp，三期方向完全一致 —— 这不是噪声，是系统性偏离。

### 这件事的意义

我在 2026-11-13 的分析里提出这套 7 维投票时，用的是"交易常识"。
检验结果说明**常识不等于有效**。因此：

- 行动卡的 `build_inference` 在收到 `inverted` 判定时，会把 `confidence`
  强制压到 `very_low`，并在 `caveats` 首位插入警告；
- 前端用红色独立展示 `RuleValidationHint`；
- 用户看到的不是"偏强（系统很确定）"，而是"偏强（**但历史上这档是反向的**）"。

### 端点

```
GET /api/action-card/{symbol}/validate-strength?step=3        单票
GET /api/action-card/validate-strength-market?limit=60&step=10 跨标的汇总
```

单票常因样本 <30 得不出结论 —— 汇总端点才是主要用法。

## 三、计划与实际成交的自动对账

### 新增函数

`position_plan.reconcile_with_fills(plan, fills, symbol=...)`

### 匹配规则（保守，宁可报未匹配也不乱认）

1. 只看该 symbol 的 `buy` 成交（`sell` 与 `corp_action` 不参与）；
2. 按时间顺序，为每个计划批次找**价格差 ≤2%** 的第一笔未被占用的成交；
3. 已手动标记 `done` 的批次直接记 matched，不消耗成交；
4. 剩余未匹配的买入成交记为 `orphan_fills`（计划外下单，或价格偏离超容差）。

### 关键设计：**只读，不自动改写计划**

自动把批次标成 `done` 看似方便，但会在"分批计划顺序与实际成交顺序不一致"时
悄悄改错 —— 而计划是**用户的意图记录**。所以只报告差异并给
`suggested_actions`，由用户决定。

### 端点

```
GET /api/position-plans/{symbol}/reconcile
```

行动卡里也带 `reconciliation` 字段，前端独立面板展示。

## 四、组合级资金校验

### 新增函数

`position_plan.check_aggregate_capital(plans, available_cash=...)`

### 关键：加总用「待执行」而不是「全部计划」

已成交的部分**已经花掉现金**，再加一遍会重复计算。所以：

```
total_planned    = Σ 所有批次金额
total_executed   = Σ done=True 的批次金额
total_remaining  = total_planned - total_executed   ← 这一项才与现金比较
```

实测：

```
计划 A: 5万(已执行) + 5万(待执行)
计划 B: 3万(待执行)
→ planned 13万 / executed 5万 / remaining 8万
→ 现金 10 万：不超支（若错误地用 planned 13万 比，会误报超支）
```

`available_cash=None` 时只报合计，**不判断够不够**（没有账户就无从比较）。

### 端点

```
GET /api/position-plans/capital-check
```

## 五、前端三态总览页

`frontend/src/custom/action-card/Overview.tsx`，路由 `/position-overview`。

包含三块：

1. **计划资金校验** —— 计划合计/已执行/待执行、可用现金、缺口预警、每标的明细；

## 七、仍然没做的（诚实清单）

1. **规则检验只在 76 只票上跑过**。全市场 5000+ 只的检验需要约 1 小时，
   目前靠端点按需触发（`limit` 可调到 200）。
2. **规则反向的原因未查明**。可能是：① 这套判据本质是"追涨"，而 A 股短期
   反转效应更强；② 样本期偏特定行情；③ 判据组合有内在冲突。
   **在查清之前不修改规则** —— 改了就无法分辨是修对了还是过拟合。
3. **对账的价格容差固定 2%**，未按波动率自适应。高波动票可能漏匹配。
4. **资金校验不区分资产类型**（ETF 的 T+0 可用资金规则未建模）。
5. **基本面只覆盖本地已落库的数据**，未公告事项、行业数据仍需人工核对。
